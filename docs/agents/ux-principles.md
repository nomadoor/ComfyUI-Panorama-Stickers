# UI と UX の原則

エディタとノード上の表示の UI を変えるときに照らす原則を定める。今の見た目の値は `docs/design.md`、
今の操作は `docs/editor-interaction.md`・`docs/timeline-ui.md`・`docs/studio-node-surface.md` が持つ。
この文書は「どう変えるか」の物差しで、今の UI がすべてを満たしているとは限らない。満たしていない所は、
UI の作業で直す候補にする。

## 決まり（オーナーが決めたもの）

- 押すたびに状態が反転するボタンは作らない。状態を持つ切り替えは、スイッチか segmented control にする。
- 別の control が出たり消えたりしても、control の位置を動かさない。各 control に決まった場所を取り、群の一員は
  隠さずに無効にする。条件付きの control は、群の外側の端に置く。変わる文字の幅は先に確保する。
- 使う人のデータを、黙って劣化させない（間引く、解像度を下げる、SH を落とす など）。速さのために質を下げるなら、
  先に提案して承認を得る。速さは原因で直す。
- 視点の操作は、一般的な 3D ツールの慣習に従う。
- UI は最小限にする。

## 原則

### 反応と速さ

- どの操作にも、すぐ目に見える反応を返す。押下・hover・drag の始まりで見た目が変わる。
- 効かない操作を黙って無視しない。無効な control、今のモードで効かないキーには、理由を短く示す
  （tooltip かステータスの一行）。
- 待ち時間は削る。モーダルとパネルの開閉、視点の移動、Undo、再生の開始は短く。位置関係を見失わないための
  遷移だけを、短く入れる。
- 待たせるときは、何を待っているかを簡素に示す（動画のデコード中、スプラットの読み込み中、代わりの表示中）。
  演出で隠さない。
- 状態が変わった瞬間（Keyframe を打った、上書きになった、snap が効いた）は、一瞬だけはっきり知らせる。
  操作は止めない。

### 見やすさ

- 操作できるもの（選択の枠、ギズモ、Camera の枠）を前に出し、背景のパノラマは一歩引かせる。背景は明るいことも
  暗いこともあるので、色だけでなく明暗の差で、どの背景の上でも見えるようにする（明るい線と暗い線を重ねる など）。
- 色は意味のあるところにだけ使う（軸、選択、Keyframe、継承と上書きの状態）。飾りの色を足さない。
- 色だけで区別しない。形、アイコン、塗りの有無、ラベルでも区別する。軸の赤と緑は見分けにくい人が多い。
  白黒にして、目立つべき所が目立つかを確かめる。
- 大事なもの、よく使うものを大きく、価値が同じ選択肢は同じ大きさにする。使う回数の少ない設定は、
  位置の決まった折りたたみに入れる。
- 情報は、使う人が見ている所に出す。ギズモを動かしている間の変化量は対象の近くに出す。
- 画面は狭い。3D ビューの面積を優先し、パネルは決まった幅のまま畳めるようにする。ノード上の表示は、
  縮小しても絵が主役のままにする。
- ビューの上に重ねる情報は最小限にし、状況で出し入れしてよい（ほかの control を動かさないので）。
  パネルの中の control は、上の「位置を動かさない」に従う。

### 分かりやすさ

- 一般的なツールの操作を借りて、説明を省く。ショートカットは近道にとどめ、同じ操作を UI からもできるようにする。
- 同じ結果に複数の入り口があってよい（ドラッグ、数値の入力、ギズモ）。
- 項目名を言い換えただけの説明にしない。この道具に固有の言葉（Inherited と Override、3DoF と 6DoF、Sky と World、
  Clip range）には、何が起きるかを平易に書いた説明を hover で添える。常に出す文字は増やさない。
- エラーは、内部の名前ではなく、原因と次にすることで書く。
- 言葉が読めなくても分かるように、種類と mode はアイコンの形でも区別する。翻訳で長くなる言葉に備え、
  枠の幅は文字の長さで変わらないようにする。
- 作り手の都合（実装の順番や内部の仕組み）を、使う人の手順に押し付けない。
- 初めての人は、長い説明ではなく実物の中で導く。空の画面には、次にすることを一行で示す（場所は先に確保する）。

### 試しやすさ

- 変えた効果をすぐ見せる。インスペクタ、Easing、Clip range の変更は、3D ビューとタイムラインにすぐ反映する。
- 再生はいつでも止められ、前後の Keyframe や Clip range の端へすぐ移れるようにする。
- 見たいものだけを見られるようにする（隠す、半透明、単独表示）。表示だけに効かせ、出力には効かせない。
  何かを隠していることは常に分かるようにする。
- 補間の既定値で、動きをぬるくしない。緩急の強い Easing や hold を、すぐ選べるようにする。押し付けはしない。
- 操作の手触り（速度、感度、刻み）は数値で決めて調律する。速度は Scene の尺度に合う単位で持ち、変えたら値を見せる。
- 3D 酔いに気を配る。慣性と揺れは控え、自動の視点移動は短くする。

### 境目

- 境目での振る舞いを、操作ごとに決める。例：Keyframe を Clip range の外へ動かす、Sky の Sticker を天頂へ動かす、
  タイムラインの終わりを越える、6DoF で原点から大きく離れる、継承元の要素が消える。一律の扱いで済ませない。
- 小さなノード、別の画面の大きさと DPI、性能の低い GPU でも見え方と速さを確かめる。

## 取り入れないもの

ゲームの手応えのための演出（画面の揺れ、強いフラッシュ、操作を止める間）、印象をよくするための絵の加工、
ロードを演出で隠すこと、迫力のための視点のずらし、ご褒美の演出、独自の世界観を持つ UI。道具の表示は
出力に忠実で、予測できるものにする。
