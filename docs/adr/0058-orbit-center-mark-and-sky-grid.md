# ADR 0058: オービットの中心を見せて指して決め、Reset View は原点へ戻し、空にグリッドを描く

## Status

Proposed（2026-11-03）

ADR 0047 の次の決定を置き換える：「`T` の印は画面に出さない」（中心を気にする時だけ印を出す）、「Reset View は開いたときの視点と同じ」
（いつも World の原点・水平・yaw 0）、Preview のウィンドウの「地面のグリッドは既定で隠し」（グリッドは既定で出す）、`T` の距離をいつも範囲（`d` は
`TARGET_MIN_DISTANCE`〜`TARGET_MAX_DISTANCE`）の中に置くこと（使う人が指した `T` は範囲に寄せず、ホイール・ジョイスティック・WASD / QE の
前に同じ線の上で範囲に戻す）。
ADR 0047 の「直接の操作は 1 対 1」は変えない（ドラッグの追従はもう一度試し、もう一度捨てた）。

## Date

2026-11-03

---

## 背景

持ち主が実機の GPU で、World の中のオービットを「マウスの DPI が高すぎるよう」と感じ、World の中の一点のまわりで視点を合わせるのが
とても難しいと挙げた（2026-11-03）。

調べて分かったこと：

- オービットの式と量は SuperSplat と同じ（`orbitView`、1 px あたり 0.3°）。量の問題ではない。
- 回る中心 `T` が見えず、決め方（ダブルクリック）がどこにも書かれていない。
- `T` はたいてい宙の遠い所にある：開いたときは前方 8、何も無い所へのホイールで 48 まで伸び、遠い地面をダブルクリックしても `T` が
  当たりの点ではなく 48 の所（宙）に寄せられていた。そのため目が長い腕で振り回される。

試作の branch（`proto/orbit-center`、マージしない）で次を作り、持ち主が実機で触って決めた（2026-11-03、最後の版で「まあいいんじゃないかなぁ」）。

## 決定

### オービットの中心

- 中心を気にする時だけ、`T` に小さな点と輪の印を出す：Alt を押している間、オービットの間、球のつまみにポインタを載せている間、
  Set orbit center に載せている間と待っている間、ダブルクリックか Set orbit center で `T` を決めた直後（少し出して消す）。
  ふだんは出さない。
- 印は World の点に置く。`T` を決めた直後は、決めた点（クリックした点）にその瞬間から出し、視点が向く間もその点に留まる。前の `T` から
  滑ってこない（試作の途中で、補間した `T` に置いて印が滑って見え、持ち主が「なんでアイコンも動いてるんだ」と挙げた）。
- 右の視点の操作の列に「Set orbit center」のボタンを足す：押すと次の一回のクリックを待ち、クリックした点を `T` にしてそちらへ向く
  （ダブルクリックと同じ）。待っている間は、ボタンを待っている見た目（氷の輪がゆっくり明滅）にし、カーソルを十字にし、上端の中央の一行に
  何をすればよいかを書く。Escape・もう一度押す・タブを変えるでやめる。Camera タブでは無効。
- ダブルクリックと Set orbit center の当たり、オービットの始めの回る中心（選んだ物の中心、Camera の位置）は、指した点そのものを `T` にする
  （距離の上限 `TARGET_MAX_DISTANCE` に寄せない）。当たりが世界の境界の外なら、空として扱う。
- 範囲の外の `T` はオービットではそのまま使い、`d` に比例する量の操作（ホイール、ジョイスティック、WASD / QE）は、動かす前に `T` を同じ線の
  上で範囲に戻す。新しい定数は足さない。
- 量の定数（`ORBIT_DEG_PER_PIXEL`、距離の定数）は変えない。

### Reset View

- Reset View はいつも World の原点・水平・yaw 0 へ戻す（持ち主の決定、2026-11-03）。Camera の位置へは戻さない。開いたときの視点は
  今のまま（出力の視点）。原点はパノラマを撮った点で、Camera をどこへ動かしても同じ所へ戻れる。

### 空のグリッドと地面の軸

- 無限遠の Sky の球に経緯線（30° ごと）を描く。地面のグリッドと同じスイッチで出し入れし、Preview でも既定で出す。
- X 軸（珊瑚）と Z 軸（氷）の経線は、地平線から遠いほど濃く、地平線へ下りるほど薄くし、地平線のそばでは描かない。ほかの線は極へ向けて
  薄れる。地平線は細い中立の線だけ。極の点は、視線が近づいたときだけ出す小さな点で、輪は描かない。
- 目のいる側の半球だけを描く（地面より下にいれば下の半球）。
- 地面のグリッドの X 軸と Z 軸は距離で薄めず、地平線まで同じ濃さで描く（グリッドの板の外は空のグリッドの層が続きを描く）。

### Camera のボタン

- Camera のボタンで Camera を動かしたら、畳んである Output の小窓を開く。
- ファインダーの合図は、かぎ括弧がすっと入ってすぐ ease-out でゆっくり抜ける動きにし、周りの光（グラデーション）をやめて、かぎ括弧の
  外を黄の 8% で平らに塗る。

規則は `docs/space-and-view.md`（「開いたときの視点と Reset View」「注視点 `T`」「マウスとキー」「カーソル」「視点の操作の部品」
「Set orbit center」「オービットの中心の印」「地面のグリッド」「空のグリッド」「Preview のウィンドウ」）、`docs/studio-ui.md`（「画面の区画」
「Output の小窓」「エディタの中の Camera」「一行の知らせの種類」「閉じ方」「ショートカットの一覧」「Preview のウィンドウ」）、`docs/design.md`
（色・大きさ・動き・アイコン・描画のくっきりさ）、`docs/threejs-spark-integration.md`（「新しい UI のステージの描画」）、`docs/preview-node.md`
（キー）が持つ。

## 理由

- 中心が見えれば、どこを軸に回っているかが分かり、振り回される感じは中心の位置で説明がつく。いつも出すと、ADR 0047 のとおり回っている
  中心に見えなかったので、気にする時だけ出す。
- ダブルクリックは知らないと見つからない。ボタンなら見つけられ、待っている間の文で何をすればよいかが分かる。
- 遠い地面を指して宙に `T` が置かれると、指した所のまわりを回れない。指した点をそのまま使い、量の操作の前だけ範囲に戻せば、速さの規則
  （`d` に比例）は今のまま守れる。
- Camera を遠くへ動かした後、Reset View で Camera の位置に戻っても「元の所」に戻った感じがしない。原点はどの場面でも同じ。
- 空を見上げたとき、地面のグリッドだけでは向きが分からなかった。軸の色が空まで続けば、どちらが X かが分かる。

## 試して捨てた案

| 案 | 選ばなかった理由 |
|---|---|
| オービットの速さ（`ORBIT_DEG_PER_PIXEL`）を下げる、`T` の距離の上限を縮める | 定数の調整で、持ち主が禁じた。式と量は SuperSplat と同じで、原因は中心が見えず遠いこと |
| 押すたびにポインタの下の点を回る中心にする | ADR 0047 で捨てた（中心が想定の場所に無く、距離が毎回変わる） |
| ドラッグに 0.2 秒の追従（SuperSplat の `TweenValue.goto(target, 0.2)`、quintic の ease-out）を付ける | ADR 0047 で一度捨て、試作でもう一度試した。持ち主が「ラグい」として捨てた |
| Alt を押すたびに上端の中央に「Double-click to set the center」を出す | 持ち主が「うるさい。そんなに頻繁に使っていいものじゃない」として捨てた。文は Set orbit center を待っている間だけにする |
| Set orbit center の待ちを、ほかのつまみと同じ強い塗り（光る）で示す | 選んでいるのか待っているのかが分からず、何をすればよいかも分からなかった |
| 空のグリッドの線を全体に濃くする | 邪魔になる。軸だけに色を付け、ほかは極へ向けて薄める |
| 極に輪と点を描く | 真上・真下を見たとき、輪が視界を塞いだ |
| 地平線に光の帯を付ける | 持ち主が「地平線の色なにこれ」と挙げた。試作では地面の軸の続きが地平線に沿ってにじみ、色の帯にも見えていた |
| 地面より下でも上の半球を描く | 下にいるときは下の半球が見えるべき（持ち主） |
| 空の軸の経線を地平線まで同じ濃さで描く | 地平線で地面の軸と二重になった。空の軸は地平線へ下りるほど薄くし、地平線では地面の軸が続く |
| ファインダーの合図の、縮んで止まる段と周りのグラデーションの光 | 持ち主が「もっとスッととってスッと出ていけばいい」「周囲はグラデーションの必要ない」とした |

## Consequences

- オービットの中心がふだんは見えないことは変わらない。中心を知りたいときは Alt を押すか、球に載せる。
- 範囲の外の `T` を持つ間は、ホイール・ジョイスティック・WASD / QE の最初の一回で `T` が同じ線の上で近づく（画面の位置は変わらない）。
- Reset View で Camera の位置に戻る入口は無くなる（Camera タブで Camera から見られる）。
- Preview のウィンドウにも一行の知らせが一つだけ（Set orbit center の待ち）入る。
- 実装で扱うこと（試作で既存の test を動かしたもの）：
  - `tests/browser/studio_inputs.spec.js` の上流の背景の色を読む点（yaw 0・pitch 30）が、空のグリッドの Z 軸の経線と 30° の緯線の上に
    来る。グリッドの線を避けた点で読むか、その場面でグリッドを隠す。
  - `tests/browser/depth_color_sync.spec.js` はステージの真ん中の行（地平線）の色を読むので、地平線の線が混ざる。その場面ではグリッドを隠す
    （試作では隠して通した。地平線の線が World の物の上に透けているのではないことを、実装のときに確かめる）。
  - `tests/browser/studio_editor.spec.js` のグリッドのスイッチの場面は、空の側の画素の変化が小さいことを前提にしていた。空のグリッドの分を
    見込んだ比べ方にする。
  - `tests/browser/studio_camera_button.spec.js` の合図の場面は、新しい動き（入る・出る・外側の塗り）と、小窓が開くことに書き直す。
- 実機の GPU で確かめること：空のグリッドの濃さと、印の見え方。headless の確認は CPU の描画で、色と濃さの目安にしない。
