# ADR 0057: ペイントのストロークを、エディタでもノードでも球面の上で描く

## Status

Proposed（2026-11-03）

## Date

2026-11-03

---

## 背景

ストロークのまとまりを球面の上で動かし回せるようにした（ADR 0056）ことで、ストロークが極の近くや極をまたぐ所へ行くようになった。実機で、
極の近くへ運んだストロークの一部が「///」のように途切れて見えた。

調べた事実（headless Chromium で、エディタのペイントのエンジンが描いた ERP を球面の上で測った）：赤道で描いたストロークを運ぶと、筆の幅の
中の穴は、緯度 87° までは 0、89° で 1.3%、89.97° で 3.5%。古い UI の Unwrap の表示で描いたストローク（`viewMode` が `"unwrap"`）では、
80° で 13%、87° で 43%、89° で 69%。原因は二つ。

- エディタのエンジンは、筆の形を ERP の画素の上で押し、横の半径を `1 ÷ max(0.05, cos 緯度)` 倍する。0.05 で止まるので、緯度 87.1° より極に
  近い所では球面の上で細くなる。`"unwrap"` のストロークは横に広げない。
- 筆を押す経路は、隣の点を ERP の上で結ぶ（直線と Catmull-Rom）。運んだ後の点は、極の近くで隣どうしが経度で大きく離れる（緯度 89.5° で 72°）
  ので、経路が大円ではなく緯線に沿って極のまわりを回る。

ノード（`core/painting.py`）は、ERP の上で点を結び、横に広げない筆の形で描く。今でも、赤道から離れたストロークはノードの出力でだけ細い。

## 決定

- ストロークを、エディタ（エンジンと、消しゴムの届く画素）でもノードでも、同じ規則で球面の上で描く（持ち主が任せ、決めた、2026-11-03）。
  規則は `docs/render-contract.md` の「ペイントのストロークの描き方」の一か所に置き、Python と JS は同じフィクスチャを読む test で揃える。
- 隣の点の間は、ERP の直線が大円から筆の縦の半径の半分より離れるときだけ、大円の中点を入れて細かくする（ふつうに描いたストロークは
  変わらない）。
- 筆の形の横の半径は `1 ÷ cos 緯度` 倍し、上限は押した形が ERP の全幅に届く所（幾何で決まる）にする。
- 描いた表示（`viewMode`）では分けない。`viewMode` は読み込みで捨てられ、開き直した後には残らないので、一つの規則にする。古い UI の Unwrap の
  表示で描いたストロークも、ほかと同じく球面の上で描く（描いている間だけ ERP の形で、開き直すと広がる今の食い違いも無くなる）。

## 試して捨てた案

- 点を運ぶときに大円に沿って点を足す（データの側で直す）：経路は直るが、筆の幅が細くなるのは直らず、保存する点も増える。
- エンジンの上限 0.05 を小さくするだけ：調整した数で、極のごく近くでは残り、経路の問題も残る。ノードとの差も残る。

## Consequences

- 極の近くへ運んだり回したりしたストロークも、途切れず、球面の上で同じ太さに見える。
- 意図した変更：ノードの出力で、赤道から離れたストロークが横に太くなり、エディタと揃う。基準画像 `stickers_paint` は、太さと、点の少ない
  古いストロークの曲がり方が大円に寄ることで、はっきり変わり、
  `stickers_paint_mask`・`stickers_paint_interleaved`・`studio_paint_interleaved` はわずかに変わる見込み。変わった理由を確かめて焼き直す。
- 古い UI の Unwrap の表示で描いたストロークは、描いた直後から横に広がって見える（開き直した後と同じ）。極を囲む投げ縄は次の候補。
- 分かっている限り：Python と JS は半径の決め方が今も少し違う（Python は直径を整数に丸める）ので、点を入れる判断がしきい値のごく近くで
  分かれることがある。押す形が全幅に届く行で一回だけ押した点は、継ぎ目の写しの縁で少し薄い帯が出ることがある。どちらも次の候補。
