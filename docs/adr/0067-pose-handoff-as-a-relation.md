# ADR 0067: Pose handoff は、撮った Camera との関係として持つ

## Status

Proposed（2026-11-17）

ADR 0036（受け取る側で、Camera のフレームごとの値を焼き込む）を置き換える。
ADR 0030 の「`sticker_state` で届く Sticker」の「下流で触った Lane だけが下流の値になる」を置き換える。
ADR 0059（Pose handoff はいつも `sky`）は変えない。

## Date

2026-11-17

---

## 背景

Pose handoff は、撮った絵を外のモデルで直して、撮った所へ戻すためのものである（ADR 0045 の往復）。今の形には二つの弱さがあった。

- 受け取る側が、撮った Camera を 1 フレームごとの Keyframe に焼いて、貼る画像の Lane にする。使う人が一度でもその Lane を触ると、Lane が丸ごと下流のものになり、上流の Camera を直しても届かなくなる。
- 動きの決まりを変えた（ADR 0064、ADR 0065）ので、焼き込みに使っていた `auto` が無くなり、Camera の向きが Look at という関係で決まるようになった。

持ち主は、取る・直す・戻すというこのノードの本質から考え直した（2026-11-17）。

## 決定

- **置き方は関係として持つ。** `sticker_state` が届いている `port` の Sticker の置き方は、「撮ったときの Camera」である。受け取った `sticker_state` を実行のたびに読み、フレームごとに撮った Camera を評価する。下流の状態には何も焼き込まない。
- **使う人の直しは、ずらしである。** ずらしは、撮った Camera から見た、もう一つの Camera との差で持つ：撮った Camera の自分の軸での向きの差（`offset_rotation`。yaw・pitch・roll、度）と、画角の倍率（`offset_fov`）。置き方は、撮った Camera にこの差を掛けたもので、差が無ければ撮った絵とぴったり重なる。画面に対する割合ではないので、レンズの曲がりによらず同じ式になる（持ち主の案、2026-11-17）。Keyframe を打てて、上流の Camera を直せば、ずらしを保ったまま付いていく。
- **切り離しは作らない。** 撮った絵を引き伸ばしたり、撮った所と関係なく置いたりすることは、取って・直して・戻すという往復と合わない。自由に置くことは、`sticker_state` をつながずに絵だけを渡せば、今もできる（持ち主、2026-11-17）。同じ理由で、縦か横だけの画角は変えられない。「元に戻す」は、ずらしを無しに戻す。
- **`sticker_state` は Camera の Keyframe のまま運ぶ。** フレームごとの中立の形にはしない。版を 3 にして、Keyframe の読み方（ADR 0064）を示す。Look at は関係のまま運ぶ（相手の Lane と、相手の物の動き・中身の箱）。ループの印と周期も運ぶ。ほかの道具は、Camera の Lane にフレームごとの Linear の Keyframe を並べて渡せば、書いたとおりに動く。座標の決まりを外向けに書くのは、受ける相手が決まったときにする。
- **置き場所は Sky のまま。** 使う人が Sky と 3D を切り替えるスイッチは作らない。3D に戻す形（奥行きを使って立体にする）は、奥行きを扱う段で足し、どちらにするかは往復が決める（ADR 0045）。
- **Box への備えは、考え方だけ。** 戻ってきた物は、取り出したときの記録に付いていて、小さなずらしを持つ。3D をくり抜いて戻す Box を作るときも同じ形にし、記録の種類は `sticker_state` の版で足す。今は種類の欄を持たない。

## 境界をまたぐ設計（AGENTS.md の原則 4）

### 作らないもの

- フレームごとの中立の受け渡しの形、座標の決まりの外向けの文書。
- Sky と 3D を切り替えるスイッチ、撮った場所に絵の札を見せる表示。
- 撮った Camera との関係をやめる操作（切り離し）、縦か横だけの引き伸ばし。
- Box と、そのための入力。
- 前の版の、上書きしていた Lane の印（`handoff_overrides`）の引き継ぎ。

### どの規則をどこが持つか

| 規則 | 持つ文書 |
|---|---|
| `sticker_state` の形と版、読み込み | `docs/scene-state-v2.md` の「`sticker_state`」 |
| 付いている Sticker の置き方の式（撮った Camera とずらし） | `docs/scene-state-v2.md` の「受け渡しの置き方」 |
| `port` の Sticker のずらしの Lane | `docs/scene-state-v2.md` の「Sticker」「Lane」 |
| ノードが `sticker_state` を作る・読む・評価関数に渡すこと、実行結果の `ui` | `docs/studio-node.md` |
| エディタでの表示、ずらしの編集、元に戻す | `docs/editor-interaction.md` |
| インスペクタのカードと下の中央のバー | `docs/studio-ui.md` |
| タイムラインの行 | `docs/timeline-ui.md` |

### data の流れ

- 撮った Studio は、Camera の Lane、Look at の相手とその動き、ループと長さを `sticker_state`（v3）に書く。
- 受け取る Studio のノードは、それを読んで評価関数に渡す。評価関数は、`port` の Sticker の向き・画角・レンズを、撮った Camera とずらしから求め、ほかの `sky` の Sticker と同じ形で返す。
- エディタは、実行結果の `ui` に入った同じ `sticker_state` を、同じ評価関数に渡して描く。保存するのは、ずらしだけである。

### 状態とデータの形の変更（AGENTS.md の Stop & ask）

- `sticker_state` の版 3（`length`、`camera.loop`、`camera.look_at`、`targets` を足す）。
- 状態の `port` の Sticker に `offset_rotation`・`offset_fov` を足し、`handoff_overrides` を読まなくする。
- 評価関数の引数 `shot`。
- 実行結果の `ui` の `pano_sticker_handoff` の中身。
- `PANO_SCENE` の層に、その層を作ったノードが決めた Timeline の長さを足す（上流の物のループの周期。ADR 0064）。層は、上流で評価されたとおりにもう一度評価するのに要るものを運ぶ。

### 一致を守る test

- Python と JS が同じフィクスチャ（`v2_handoff`、`sticker_state_v3`）を読む：ずらし 0 で撮った Camera そのままになること、ずらしを掛けた置き方、カット、Look at を関係のまま渡した向き、ループ。
- 輪の閉じ方（同じ Camera で撮り直すと元の画素に戻る）の test は、焼き込みではなく評価で通す。

## 後方互換

- 前の版が保存した `handoff_overrides` は読まない。前の版で引き継いだ Lane を直していた `port` の Sticker は、直しが消え、撮った Camera にそのまま付く。持ち主は、保存済みのものが変わることを受け入れている（ADR 0063）。
- v2 の `sticker_state` は、Keyframe を今の決まりで読む（欠けた Easing は v2 の既定の ease-in-out、`auto` は Smooth）。前の版の計算は残さない（持ち主、2026-11-17：互換の一部は捨ててよい）。v1（旧ノードが出す、姿勢一つの形）は今までどおり読める。

## 考えた別案

- **焼き込みを続け、Easing を Linear に変える**：一度触るとつながりが切れる弱さが残る。
- **フレームごとの中立の軌道にする**：ほかの道具には書きやすいが、Studio どうしでは Keyframe の少ない元の形が失われる。ほかの道具は、今の形にフレームごとの Linear の Keyframe を書けば同じ結果になるので、採らない（持ち主）。
- **Look at の結果を、渡す側でフレームごとに焼く**：関係のまま渡せば、受け取る側でも同じ規則で求められる。焼くと、渡すデータだけが別の形になる。
- **Sky と 3D を使う人が選ぶ**：絵だけでは奥行きが分からず、Camera の前の板は撮った場所からしか重ならない（ADR 0059）。奥行きが手に入る段で、道具が決める。
- **切り離して、ふつうの Keyframe に書き出す**：撮った絵を自由に動かすことは往復と合わず、`sticker_state` をつながなければ今もできる（持ち主）。
- **ずらしを、撮った画面に対する割合で持つ**：レンズの曲がりがあると、割合から角度への直し方が一つに決まらない。Camera の差で持てば、直しが要らない（持ち主の案）。
- **撮った場所に絵の札を見せる**：エディタには見えて出力には写らず、空に貼った絵と二重になる。

## Consequences

- 上流の Camera を直すと、下流の直し（ずらし）を保ったまま届く。
- 受け取る側の実行の前処理（Camera の Keyframe の範囲の焼き込み）が無くなる。
- `port_sticker.py` の焼き込みと上書きの部品、`pano_port_handoff.js` の表示と保存の組の部品は、消すか作り直す。
- 次の候補：奥行きで 3D に戻す形、Box。
