# ADR 0041: Preview は編集から分けた「見る場所」で、`PANO_SCENE` を 6DoF で動き回って見る

## Status

Accepted（2026-10-10）

## Date

2026-10-10

---

## 背景

新しい Preview（`PanoramaPreviewNode`）は `PANO_SCENE` を素通しするだけで、何も見せない。さらに、このノードにはノード上の表示がまだ無い（`isPanoramaPreviewNodeName` が新しい id に当たらない）ので、IMAGE と VIDEO も見えない。

## オーナーが決めた Preview の目的（2026-10-10）

- 見る場所で、編集とは分ける。Studio のエディタでは Sticker に触れてしまうので、気楽に眺める場所にならない。Preview では何も編集できない。
- 触って楽しい：6DoF で自由に、気軽に動き回る。
- ノードの上でも、大きなウィンドウでも見られる。
- 歩くモード（SuperSplat のように、床と壁に当たりながら一人称で歩く。別の粗いボクセルの当たりの素材を使う）は後の段階。
- Camera は使わない。Camera があると Studio の出力は ERP ですらない。Preview は Scene そのものを見せる。
- Preview のノードがいくつあっても、動くのは最後に操作した 1 つ（オーナーの決定）。

## 決定

- 描くのは、エディタの空間の表示と同じ 3D の表示（three.js、Spark、深度のグリッド、上流の層の要素、既定の照明）。出力の画素ではなく、出力との差はエディタと同じ（差の一覧は `docs/threejs-spark-integration.md`）。
- 入力ごとの見方：`PANO_SCENE` は 6DoF で動き回り、IMAGE・VIDEO の ERP は 3DoF で見回す。Timeline に沿って VIDEO と動く 3D を再生する。
- 編集の UI は一つも出さない。出力のポートは入力を素通しし、ノードの id は変えない。
- データ：Preview の実行は描かず、Studio が上流の Scene に返すのと同じ `ui`（`_upstream_ui`）を返す。
- 継ぎ目：エディタの視点の操作の配線（`editor/space.js`）と上流の層の組み立て（`editor/upstream.js`）を、エディタから独立したモジュールに分ける（振る舞いを変えない整理を、最初に別の commit で行う）。エディタとビューアの両方がそれを使う。ビューアはノード上では今ある共有のビュー（1 つの WebGL の context）で描き、ウィンドウでは `PanoModal.vue` の `viewer` の配置で描く。
- 動くのは最後に操作した Preview の 1 つで、ほかは最後に写した絵のまま。各ノードは自分の視点を持つ。
- 再生の帯：ノード上とウィンドウで同じ 1 本（再生と一時停止のボタン 1 つ、シークの帯、時刻の表示）。時間の無い入力では無効にして場所を保つ。再生と一時停止のボタンはメディアプレーヤーの慣習どおり押すたびに切り替わる（オーナーの決定。`docs/agents/ux-principles.md` の例外）。部品は今ある `PanoVideoTransport.vue` を使えるなら使う。

## 考えた別案

| 案 | 選ばなかった理由 |
|---|---|
| バックエンドで最初のフレームの ERP を描いて見回す（最初の案） | 動き回れない。オーナーの目的（6DoF で気軽に見る）に合わない。Preview の実行ごとに描画が要る |
| Studio のエディタを読み取り専用で開くだけ | 編集の UI が出て、見る場所にならない。ノードの上で見られない |
| エディタ全体を `viewer` のモードにしてノードの DOM に載せる（前の案） | エディタはモーダルとして作られていて、ノードの中で動くかが確かでない。載せるとエディタの状態・UI の状態・自分の WebGL の context もノードに持ち込む。視点と上流の層の部品だけを分ければ、ノード上は今の共有のビューで描け、エディタとも同じ部品になる |
| ノード上の表示のために空間の表示の組み立てを新しく書く | エディタの視点の操作の配線と上流の層の組み立てを写すことになり、規則の owner が二つになる |
| 見えている Preview のノードをすべて動かす | WebGL の context はノード上の共有のビューの 1 つのままだが、Scene ごとに読み込んだ要素と Spark の描画をノードの数だけ持つ。オーナーは 1 つだけ動かすと決めた |

## Consequences

- Preview の実行は描画もファイルの書き出しもしないので、速い。見えるものは Studio のエディタの空間の表示と同じで、出力の画素とは同じ差がある。
- Scene を作った Studio の temp のファイルが消えると、Preview でもエディタと同じく読めなくなる。入力を変えずに実行し直してもキャッシュの出力が返り、ファイルは書き直されない。Studio の入力を変えて実行すると戻る。
- 分けたモジュールをエディタと Preview が共有するので、視点の操作と上流の層の描き方の変更は両方に効く。
- 最初の 1 本の止める条件（`docs/preview-node.md`）：分ける整理がエディタの test か振る舞いを変える、分けたモジュールがエディタの状態なしに動かない、共有のビューで空間の表示を描くとほかのノード上の表示が変わる。どれかなら止めて報告する。
