# ADR 0054: 深度の格子の色を描いている要素に合わせ、止まっている間に先読みし、実行中は放す

## Status

Proposed（2026-10-31）

## Date

2026-10-31

---

## 背景

持ち主が RunPod（ブラウザから proxy 越しにつなぐ ComfyUI）で、`world` に MoGe の動画（深度の格子の列）をつないで再生したところ、
形だけが止まって色の動画だけが進んで見えた（2026-10-31）。調べると、再生中は形を「読み込み済みで一番近い前の要素」で描き、色を
再生ヘッドの時刻で描いていた。1080p の深度は 1 要素 8.3 MB で、proxy 越しでは再生に追いつかない。さらに、読み込んだ要素を
「使っていない古いもの」から捨てていたため、上限に収まらない長いループでは次の周の先頭から捨てて毎周読み直していた。

## 決定

- 色は描いている形の要素に合わせる。代わりの要素を出している間はその要素の時刻の静止画にし、色が着くまで形も進めない。
  遅い回線では形と色が一緒に止まる（形と色が食い違うより良い、と持ち主が選んだ）。
- 捨てる順は、使っていない要素のうち再生の順で次に使うのが一番遠いもの（ループ対応）。
- 新しい Studio のエディタを開いていて再生していない間は、上限まで先読みする（DaVinci Resolve のように、待てば滑らかに再生できる）。
  読み込み済みを示す帯は出さない（持ち主：邪魔）。
- ComfyUI のキューが残っている間（`status` の `queue_remaining`）は先読みを止め、表示と前方の先読みの分のほかは放す（同じ PC で
  生成とブラウザがメモリと GPU を分け合うため。持ち主：生成に迷惑をかけない）。閉じたら全部放す。
- 規則は `docs/threejs-spark-integration.md` の「空間の表示」の `scene` の項が持つ。

## 試して捨てた案

- 形が届くまで再生ヘッドを止める：遅い環境では再生が何度も止まり、時計どおりに進む再生の規則を変える。
- エディタ用に軽い深度（解像度 1/2・float16 など）を作る：ADR 0039 の「間引かない」を変える。持ち主が作らないと決めた。
- 閉じても残すキャッシュ（ブラウザの保存領域）：1 要素が重く容量を使う。今回は作らない。

## Consequences

- 遅い回線でも形と色がずれない。止まって待てば、上限に収まる長さなら滑らかに再生できる。
- 1 周目と、上限に収まらない長い入力のカクカクは残る（転送量そのものは減らしていない）。
