# ADR 0030: 引き継いだ Scene は下流で編集できる

## Status

Accepted

## Date

2026-10-05

## Supersedes

- ADR 0029 の「受け取ったノードでは、上流の要素は見えるが選べず動かせず、上流のノードで直す」と「上流の要素は自分のタイムラインに出さない」
- ADR 0029 の Consequences の「`sticker_state` が渡すのは Camera の向きと画角で、位置は渡さない」
- `docs/scene-state-v2.md` の「状態に入った `port` の Sticker には、あとから `sticker_state` を当てない」

---

`scene` は Scene 全体の設定として下流へ引き継がれ、受け取ったノードはそれを自分の要素と同じように編集できる。上流の要素を選び、動かし、Keyframe を打ち、消せる。

下流の `state_json` には、上流の要素への変更だけを、上流の要素の id ごとの上書きとして保存する。変えていない所は上流のまま引き継ぐので、上流を直して実行すれば下流に届く。上書きは Lane 単位で、下流で触った Lane は下流の Keyframe が上流の Lane を置き換える。

下流で上流の要素を消すと、下流の状態に「この id はここで消した」記録だけが残る。消した要素はエディタ、タイムライン、出力、さらに下流へ渡す `scene` のどれにも出ない。上流でその要素が消えると、下流の上書きと消した記録も捨てる（上流で消して実行すれば下流でも消える）。

ADR 0029 は、要素の正を一か所に保つために上流の要素を読み取り専用にした。これは利用者に一つの選択肢として示さないまま決まっていた。`scene` は各ノードを通るたびに引き継がれて手を加えられる設定であり、読み取り専用は利用者の理解と合わない。上書きの形にすれば、上流の変更が届くことも保てる。

## `sticker_state` で届く Sticker

`sticker_state` で届く `port` の Sticker も、上流の要素と同じく引き継ぎと上書きで扱う。動きは実行のたびに `sticker_state` から引き継ぎ、下流で触った Lane だけが下流の値になる。これで、`sticker` と `sticker_state` をつなぐ順番に関わらず上流の Camera ワークが届き、上流の Camera ワークを直したときも下流に届く。

上流の Camera の位置がどこかのフレームで原点から離れるとき、届く Sticker は `world` の Sticker とする。Camera の前方、距離 2 の位置に、Camera の回転で、画角いっぱいの大きさ（幅 `2 · 2 · tan(hFOV ÷ 2)`）で置き、Camera が動けば毎フレームの位置・回転・大きさを Keyframe に焼く。上流の Camera の位置から見れば、距離によらず撮った絵と一致する。距離は下流の視差と、下流の 3D との前後関係にだけ効く。Camera が原点から動かないときは、これまでどおり `sky` の Sticker とし、既存の結果を変えない。`sticker_state` の形式は変えない（位置の Lane はすでに入っている）。

## Consequences

- 上流の要素は不透明で、出力と同じ見た目で描く。上流から来たことは選択時やタイムラインで示す。
- タイムラインに上流の要素の行が出る。
- 状態 v2 に、上流の要素の上書きと消した記録の項目が増える（形は `docs/scene-state-v2.md` で決める。Python と JS で同じ結果になるフィクスチャを足す）。
- 下流で上書きした要素は、さらに下流へは上書き後の姿で渡る。
- 上書きを元に戻す操作（上流の値に戻す）を持つ。
- 上書きは Lane 単位とする（位置だけを下流で動かしても、回転などほかの Lane は上流の変更を受け続ける）。
- 距離 2 は、あとでエディタから見かけの大きさを保ったまま奥行きを変えられるようにする（UI の作業）。
- `docs/render-contract.md`、`docs/scene-state-v2.md`、`docs/timeline-ui.md`、CONTEXT.md の Pose handoff の項を直す。
