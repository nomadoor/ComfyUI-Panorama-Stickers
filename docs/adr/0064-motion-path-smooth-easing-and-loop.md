# ADR 0064: 軌道の形と緩急を分け、何も設定しない動きを Smooth にし、ループを物ごとに持つ

## Status

Proposed（2026-11-17）

ADR 0026 の「Easing の既定値は ease-in-out」「`auto` は Keyframe で止まらずに通過する」と、cubic-bezier の区間が端の値の間をまっすぐ進むことを置き換える。
ADR 0038 の Drone の項の「止まらずに複数の点を通る動きは、Keyframe の `auto` でできる」を置き換える。

## Date

2026-11-17

---

## 背景

持ち主が試して、次のことが分かった（2026-11-14〜17）。

- 全部の区間を Linear にしても、ひと続きの滑らかな Camera の動きにならない。cubic-bezier の区間は端の値の間をまっすぐ進むので、途中の Keyframe で軌道が角になる。
- 曲がる軌道は `auto` にしか無く、新しい UI の Easing のパネルには `auto` が無かった。足しても、何をするものかを絵にできず、分からなかった。
- 最初と最後に同じ値の Keyframe を置いても、滑らかにループしない。
- 原因は、一つの Easing が「区間をどの速さで進むか」と「区間がどんな形か」の二つを決めていたことにある（持ち主：「軌道と、時間の 2 つが混ざっていない？」）。

一度、形と速さを分ける実装を作ったが（手元だけ。公開していない）、軌道の線そのものをつかんで曲げる操作、説明の無い Auto、全体で一つのループのスイッチが分かりにくく、持ち主は採らなかった（「直感的でもなければ使いやすくもないし、専門的ともライトユーザー向けでもない」）。考え方から決め直し、触れるモックで一つずつ確かめた。

## 土台にする決まり

1. **Keyframe は、動かない時刻の錨である。** Keyframe の `frame` は、最初と最後の絵から動画を作るモデルなどが頼りにする時刻である。使う人が自分でドラッグしたとき以外、どの操作も Keyframe の `frame` を動かさない。上流や、エディタの外で書かれた Keyframe も同じ。
2. **画面でできることは少なくてよいが、データは何でも表せる。** 保存する状態は、ほかの道具が座標を直接書いたもの、生成したもの、動画から推定したものをそのまま表せて、後から同じ画面で直せる。
3. **何が写るか、どこを通るか、いつ・どんな緩急で動くかを、別々の場所で決める。** 一つの操作は、一つの問いにしか答えない。軌道を直しても速さは変わらず、Easing を変えても軌道は変わらない。

## 決定

### 形と進み具合

- 区間の値を、形（軌道・回転の経路）と、進み具合（形に沿った長さの割合）に分ける。形は Easing によらず、途中の Keyframe を滑らかに通る。Easing は進み具合だけを決める。
- 位置の自動の形は、Keyframe の値の並びだけで決め、時刻を使わない。円の上に並べた Keyframe は円弧になる。持ち主が三つの場面で見て、違和感が無いと確かめた形である。
- 回転と `direction` の形も、Keyframe の値の並びだけで決め、時刻を使わない（持ち主、2026-11-17）。初めは時刻を使っていたが、それでは Keyframe の時刻を直すだけで経路が曲がり（Constant speed で最大 20° ほど）、パノラマでは見る向きの経路と地平線の傾き方が知らないうちに変わる。After Effects の Rotation や Blender・Maya の軸ごとのカーブでは向きの経路が時刻に依存するが、上の原則 3（どこを通るかと、いつ通るかを別々に決める）を向きにも当てる。
- 進み具合は、形に沿った長さで測る。

### 点の種類

- 軌道は 3D タブに線で描き、ペンツールと同じ作法で直す。点の種類は Auto（自動で滑らか）・Bezier（書かれたハンドルで滑らか）・Corner（角）。
- 状態に足すのは、位置の Keyframe の「角」の印一つだけである。ハンドルは今ある `handles` を使う。
- 点の種類は、下の中央のバーに、ギズモの切り替えと並べていつも出す。物を選んで動かすことと、再生ヘッドの Keyframe を直すことは同じ操作だからである。

### Easing

- 何も設定しない区間を Smooth と呼ぶ。動きの始まりと終わりではゆっくり出て止まり、間の Keyframe は前後と速さをつないで止まらずに通る。Easing が書かれていない Keyframe が Smooth で、保存するテキストにも書かない。
- プリセットと手で曲げた曲線は、書かれたとおりに進む。前後に合わせて進み方を変えるのは Smooth だけである。Linear が続くと、区間ごとの速さが違えば Keyframe の所で速さが変わる（受け入れる。そろえるには Smooth にするか、Keyframe の間隔を直す）。
- `auto` は無くし、読み込みで Smooth にする。
- Easing の対象は、選んだ Keyframe が一つならその次の区間、二つ以上なら一番左から一番右までの全部の区間。プリセットは、対象の区間のそれぞれに同じものを書く。
- 区間の途中に Keyframe を入れても、入れただけでは動きを変えない。Smooth は Smooth のまま、`hold` と Linear はそのまま、ほかの曲線は同じ動きになるように二つに分ける。

### ループ

- ループは物ごと（Camera と、置いた物のそれぞれ）の印で持つ。周期は出力の長さ。
- ループは、使う人がオンにしたときだけ働く。最後の Keyframe が最初と同じでも、勝手にループにはしない。行って戻って止まる動きと見分けが付かないこと、「ぴったり同じ」は少しの差で外れること、状態として書けないとほかの道具が指定できないことが理由である。
- 最後に最初と同じ Keyframe を置いたとき、その Keyframe は自分の `frame` に留まる（土台の 1）。軌道は継ぎ目で折れない。

### Simplify

- 細かい Keyframe を、形と通る時刻を保ったまま減らす命令を持つ。残す Keyframe の `frame` は動かさない。残した Keyframe の間は、ハンドルと Easing を元の動きに合わせて書く。押すと、形を保てる数まで一度減らし、そこからスライダーで、使う人が残す数を決める（形が変わる所まで減らしてもよい。繰り返し押せる）。

## 境界をまたぐ設計（AGENTS.md の原則 4）

### 作らないもの

- 値ごとのグラフを手で描く編集、cubic-bezier の縦方向を 0〜1 の外へ出すこと（行き過ぎる動き）。
- 向きの動き（`rotation`・`direction`）の軌道の線と点の種類。向きの形は今の規則のまま。
- 物の複数選択、Camera のショットの命令（Orbit など）、手ぶれなどのノイズ。
- 前の動きを再現する読み替え。

### どの規則をどこが持つか

| 規則 | 持つ文書 |
|---|---|
| 状態の形（Keyframe の `easing`・`corner`・`handles`、`loop`）、形と進み具合の式、ループの評価 | `docs/scene-state-v2.md` |
| 記録の規則（途中に入れた Keyframe）、Easing の対象、動きのループの切り替え、Simplify | `docs/timeline-ui.md` |
| 軌道の線と点の種類の画面、Easing のパネル、下の中央のバー、タイムラインのバーの並び、文言 | `docs/studio-ui.md` |
| 当たりの幅などの量 | `docs/space-and-view.md` |
| 色・太さ・アイコン | `docs/design.md` |
| control を選択で出し入れしない決まり | `docs/agents/ux-principles.md`（ADR 0066） |

### data の流れ

- エディタは状態に Keyframe・`corner`・`handles`・Easing・`loop` を書く。評価は Python（ノードの出力）と JS（エディタの表示と軌道の線）が同じ規則で行う。
- エディタの軌道の線は、評価関数と同じ補間の部品で描く（線の形を別に持たない）。
- ループの周期（出力の長さ）は、評価関数が呼び出し側から受け取る。
- Simplify と、途中に入れた Keyframe の分け方は、エディタだけの操作で、結果はふつうの Keyframe である。

### 状態とデータの形の変更（AGENTS.md の Stop & ask）

- Keyframe の `easing` に `"smooth"` を足し、書かれていない `easing` を Smooth と読む。`"auto"` と読めない値も Smooth と読む（今の `auto` の規則は無くなる）。
- Keyframe に `corner` を足す。`handles` は今の形のままで、点の種類（Auto・Bezier・Corner）は `corner` と `handles` から決まる。
- `position` の Lane の補間を、形（弧の長さに沿った進み）と進み具合に分ける。保存の形は変わらないが、同じ状態から出る動きが変わる（下の「後方互換」）。
- `camera.loop` と、Sticker の `loop` を足す。
- 評価関数の引数 `length`（ループの周期にする出力の長さ）。
- `PANO_SCENE` の層と、実行結果の `ui` の `pano_upstream_layers` に、その層を作ったノードの Timeline の長さを足す（上流の物のループの周期）。

### 一致を守る test

- 形と進み具合、ループは、Python と JS が同じフィクスチャ（`tests/fixtures/scene_state/` の `v2_shape_progress`・`v2_loop`）を読み、1e-4 以内で一致させる。
- 今あるフィクスチャの期待値（`auto` を含むもの、既定の Easing に頼るもの）は作り直す。

## 後方互換

- 状態の版は 2 のまま。足すのは、無ければ今までどおりの項目（`corner`、`loop`）と、Easing の書かれていない Keyframe の読み方である。
- 今の版が書いた状態は、どの Keyframe にも Easing が書かれているので、cubic-bezier の区間はそのまま読める。ただし形の規則が変わるので、位置の Keyframe が 3 つ以上ある動きは、途中の Keyframe で軌道が滑らかに曲がるようになる。`auto` を使っていた状態は、動きの端がゆるむ。
- 持ち主はこの変化を受け入れた（2026-11-15「最悪破壊してもいい」。ADR 0063 と同じ考え）。
- 古い版でこの版の状態を開くと、足した項目は読まれずに消え、Smooth は ease-in-out として読まれる。

## 考えた別案

- **Keyframe ごとの「止まる／通る」の切り替え、Keyframe ごとの Ease In・Ease Out（DaVinci Resolve 式）**：区間ごとの曲線をパネルで見せて手で曲げる今の形を保てない。
- **選んだ範囲に一つの緩急をかける**：Keyframe の時刻を守ると、Smooth とほとんど同じ動きにしかならず、グラフを手で曲げられず、Linear もまっすぐにならない。
- **範囲の中の Keyframe を時間の上で動かして、全体を一つの曲線にする（After Effects の Rove Across Time）**：Keyframe の時刻が動くので、土台の 1 に反する。
- **Auto を Easing の選択肢に残す**：何をするかを一つの区間の曲線として描けない。Smooth は、何も設定しない状態そのものにした。
- **軌道の線そのものをつかんで曲げる**：ほかの道具に無い操作で、見えない決まり（放すとまっすぐになる、ダブルクリックで戻る）が増えた。
- **全体で一つのループのスイッチ**：扇風機は回り続け、Camera は一度だけ寄る、ができない。
- **点の種類を、点を選んだときだけ出す／タイムラインのバーに置く**：control が選択で出入りする。タイムラインのバーは、点から遠い。
- **Simplify を小さな窓（ポップアップ）で調整する、押すたびに減らす**：control が突然出る。押すたびに減る作りは、どこまで減るかが分からない。

## Consequences

- 途中の位置の Keyframe は、どの Easing でも滑らかに通る。角は Corner で作る（`hold` は Cut のまま）。
- Python と JS の評価関数を作り直す。エディタの `evaluateCamera`・`evaluateSticker` の呼び出しは、出力の長さを渡すようになる。
- Pose handoff（`sticker_state`）は、Keyframe の読み方（Smooth、`auto`）に関わる。`sticker_state` の版と、受け取る側の置き方は ADR 0067 が定める。
- 上流の物のループの周期のために、`PANO_SCENE` の層が、その層の出力の長さを運ぶようになる。
- 次の候補：物の複数選択、向きの軌道の線。
