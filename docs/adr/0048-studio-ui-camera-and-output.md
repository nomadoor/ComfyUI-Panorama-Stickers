# ADR 0048: 新しい画面の形、いつもある Camera、入口の役割、出力の大きさ

## Status

Proposed（2026-10-30）

「画面の骨組み」のうち、インスペクタの決定（タブごとに映すもの、いつも出ている撮影のカードは置かない）、Camera タブの「ドラッグはいつも Camera を動かす・物は動かさずに選ぶ」、Camera タブの Output の小窓を薄く無効にする決定を、ADR 0051 が置き換えた（2026-10-31）。

「Camera タブで使えない部品は隠さずに同じ席で無効にする」を、Camera 自身の下の中央のバーについてだけ ADR 0055 が置き換えた（2026-10-31）。

## 背景

ADR 0044 は Panorama Studio のエディタと新しい Preview のウィンドウの UI の層を組み直すと決め、ADR 0045・0047 と
`docs/space-and-view.md` で「空間と視点」を決めた。作り始める前に、オーナー（デザイナー）と「何を目指すか → 機能 → 画面の構成 →
デザインシステム」の順にすり合わせた（2026-10-29〜30）。見た目と配置は HTML の見本（コミットしない下書き）を見ながら決めた。
この ADR は、その決定のうち理由を残すべきものと、試して捨てた案を残す。規則そのものは次の living spec が持つ。

## 決定

### 目指すもの

- 画像か動画を 3D に持ち上げた空間を開き、**見て回り、物を置き、撮る**。撮った絵や動画は下流の生成 AI でリファインする。
  画面はこの「見る・置く・撮る」を何より気持ちよくする。
- 置く：物を空間に置き、位置・向き・大きさを合わせる。モデリングはしない。動かす：位置と向きを時間に沿って動かす（歩くモーションの
  人を道に沿って進ませる、など）。凝ったアニメーションの道具にはしない。
- 使う人は画像や動画の編集に慣れていない人を主に考え、説明なしで分かることを一番にする。プロの使い方は近道と細かい設定で足し、
  初めての人の道をふさがない。ComfyUI を使う人を一番に考え、3D ツールの慣習はその人たちに自然なときだけ借りる。
- 撮ったものを戻す流れは今は Sky だけで、3D の切り抜き（Box。ADR 0045）は席だけを取る。

### 画面の骨組み

- 一つの画面で、タブは 3D と Camera の二つ。Unwrap のタブは無くす（主役が 3D になり、3D と平らに開いた絵を同じ列に並べると「どちらに
  いるか」がまた分からなくなる）。Camera タブは「撮る Camera から出力をそのまま見る」タブで、Panorama モードのときは Camera の位置から
  描いた ERP を平らに開いて見せるだけにする（Unwrap の役目はここが引き継ぐ）。タブを「Frame」と呼ばないのは、撮り方のモードの Frame と
  重なり、Panorama モードでは見えるものと名前が合わないためである。撮る道具の呼び方は Camera に一本化し、「Shot」は使わない。
- ヘッダーは作らない（ステージの面積を減らさない）。道具はステージの上に浮かせ、インスペクタは右の縦いっぱいの列、タイムラインは
  ステージの下。インスペクタを縦いっぱいにするのは、Easing の曲線（1:1）を置くためである。
- Camera タブは Camera を動かす画面にする（ドラッグはいつも Camera を動かす）。物は動かさずにクリックで選べ、選択は回る中心と
  Frame Selected にだけ使う（選べないとオービットの中心を物に合わせられない）。カメラファーストにし、FOV・Lens・Roll の目盛りを
  フレームの左・右・下に沿わせる。Camera タブで使えない部品（左の道具、Reset View）は、隠さずに同じ席で無効にする（オーナー。
  `docs/agents/ux-principles.md` に書いた）。
- インスペクタは「今触っているもの」を映す：3D タブでは選んだ物（Camera を選べば Camera のカード、何も選んでいなければ Scene のカード）、
  Camera タブでは Camera のカードだけ。3D タブでは Camera も物の一つで、いつも出ている撮影のカードは置かない（いつも置く理由だった
  「Camera があるか分からない」は、Camera がいつもあり Camera タブがあるので当てはまらない）。

### Camera はいつも一台あり、撮り方はモードで選ぶ

- Panorama Studio の Camera はいつも一台あり、消せない。既定は原点・回転 0 の Panorama モードで、今までの「Camera が無い」ときと同じ
  出力になる。状態の `camera` の `null` は既定の Camera として読む。
- 撮り方は Camera のモード Panorama（ERP）/ Frame（透視投影）で、使う人が Camera のカードで選ぶ。画面の言葉は Panorama と Frame
  （Perspective は透視図法に聞こえ、Standard・Photo・Flat は意味が弱いか静止画に読めるので採らない）。今までの暗黙の決め方（Camera が無ければ
  原点の ERP、比率のプリセットの最後の「360°」なら ERP）は置き換える。両方のモードの値を持ち、行き来しても値は消えない。
- Panorama モードの ERP は Camera の位置と向きから撮る（好きな位置からパノラマを撮れる今の機能を残す）。原点へは Camera の
  カードの Position と Rotation の行のリセットで戻す（専用のボタンは置かない。行のリセットはその行の値だけを戻す規則を崩さない）。
  Camera のカードは両方のモードで同じ行を並べ、効かない行を灰色にする（行の位置が動かない）。出力の種類を変えても Camera は動かさない（外の操作で中のカメラが勝手に動くのはストレスになる）。
- タイムラインの目で Camera を隠すのは表示だけで、出力を変えない（`docs/agents/ux-principles.md` の「表示だけに効かせ、出力には
  効かせない」）。
- 左の列の Camera のボタンは「今の構図へカメラを持ってくる」：Panorama モードなら Frame モードにしてから持ってくる。Blender の
  Align Camera to View と同じ使い方で、初めて押した人には枠のついたカメラが出る。押すことは編集（Undo の 1 段、Keyframe があれば打つ）。
- 3D タブでは Camera を選んでいるとき、Camera のまわりを回る（ADR 0047 の「Camera は回る中心に数えない」を置き換える。数えないと
  Camera を物として扱いにくい。除外の理由だったパンの効かなさは、パンを掴んだ点の深さで動かすようにしてから当てはまらない。
  残る心配（中心までの距離が 0 に近いと WASD などが遅い）は試作で確かめる）。
- 3D タブの Camera の見た目は、Frame モードは薄く塗った三角錐、Panorama モードは薄く塗った球と赤道の輪と正面の矢印（360° で撮って
  いると形で分かるように）。

### 出力の大きさと背景の範囲

- 出力の大きさは ComfyUI の Resolution Selector と同じ形：`megapixels`（小数）と `multiple`（整数）をノードの上に置き、出る大きさを
  先に見せる。`output_size`（横幅のコンボ）と `auto` はやめる。横幅 2048 と書いてあるのに Frame の出力が 376 px になるなど、何が出るか
  が分からなかった。生成 AI に渡す大きさは決まっていてほしいので、背景に合わせる `auto` も要らない（背景が無いときの `auto` は結局
  決め打ちの値だった）。既定は 2.0 MP で、Panorama 360 なら今の既定と同じ 2048 × 1024。Panorama（ERP）は 2 : 1（180 は 1 : 1）を厳密に保つため、
  高さを先に決めて幅をその倍数にする（Resolution Selector のように幅と高さを別々に丸めると 2 : 1 から外れる）。式は `docs/studio-node.md`。
  `megapixels` の範囲もコアと同じ 0.1〜16（わざわざ小さくしない）。選んだ値が黙って縮まないよう、長い辺の上限 `STUDIO_MAX_OUTPUT_SIDE`
  を全部のモードで 8192 に上げる（16 MP・4 : 1 で 8192 × 2048）。出る大きさはノード上の表示の上端の一行で見せ、`io.ResolutionPreview` は
  使わない（その widget は隣の文字列の widget の `W:H` を読むので、`state_json` の中の比は読めない。比を文字列の widget にも持つと同じ値が
  二か所に住む。Resolution Selector の表示は Node 2.0 でしか出ない）。
- `coverage` は名前を「背景の範囲」（`background_range`）に変え、背景の絵が球のどこまでを覆うかだけを表す。二値の 360 / 180 は残す（Unity の
  Panoramic skybox の Image Type 360 / 180 という前例がある。角度で自由に決める案は、使う人が数字を決めることになり、かえって分かり
  にくい）。出力の範囲（360 / 180）は Camera の Panorama モードの設定で、背景の範囲とは独立にする。VR180 を VR180 で出すときは二か所を
  180 にする。
- ノードの上に残すのは `background_color`・`background_range`・`megapixels`・`multiple`。Camera の構図と撮り方のモードはエディタ（Camera のカード）。
- Panorama Studio は main に無いので、既存のワークフローを移す手順は持たない。旧ノードの `coverage`・`output_size` は変えない。
- 境界をまたぐ設計（作らないもの・規則の持ち主・データの流れ・一致を守る test）は `docs/studio-node.md` の「撮る Camera と出力の
  大きさの設計」。

### 入口の役割と名前

- 入力を役割で分ける（今の `scene` は一本の入口に「別の Studio の Scene のまるごと」と「その場所の土台の 3D」の二つを刺していて、
  刺すたびに「これは Scene か土台か」と迷う元だった。土台（選べない・消せない）と Sticker（選べる・動かせる）はデータの中ですでに
  別物で、足りなかったのは入口の名前だった）。順は `scene` → `background` → `world` → `sticker` → `sticker_state`（受け継ぐ空間から、
  奥の背景から手前の置く物へ）。出力は入力と鏡にそろえ、`scene` を一番上にする（Studio どうしの線が上どうしでまっすぐになる）。
  - `scene`：別の Panorama Studio の `PANO_SCENE` だけ（Studio をつなぐ専用の入口。用語集の Scene＝全体と意味が一致する）。
  - `background`：背景のパノラマ（今までの `bg_media`）。設定は `background_color`・`background_range`。
  - `world`：その場所の土台の 3D（MoGe・DA3・3DGS・メッシュ）。動かさない（パノラマを撮った点から背景と重なるように作られていて、
    動かすと背景とずれる。合わせるのは地面の高さだけ）。
  - `sticker`・`sticker_state`：足す物と、その置き方。名前は今のまま（`sticker_state` は位置と向きだけでなく画角とレンズ、時間を持つ
    こともあるので、pose・track・camera はどれも中身の一部しか言い表さない）。複数の Sticker（ComfyUI の Autogrow）は、`sticker` と
    `sticker_state` を組で増やす必要があり、今は安定して作れないので後に回す。
- `scene` と `world` を両方つないだら重ねる（3D は奥行きで混ざる。上流の土台が要らなければタイムラインの目で隠せば差し替えになる）。
- 背景は、自分の `background` がつながっていれば上流の背景と差し替え、つながっていなければ受け継ぐ（今までの「上流を優先し、自分の
  背景は警告して使わない」をやめる。直したパノラマで背景を差し替えるのは往復そのもので、つないだものが黙って無視されないように）。
- 新しい Preview の `coverage` も `background_range` にする（Studio と同じ名前と意味）。旧ノードの名前は変えない。
- 画面の言葉は `CONTEXT.md` の「画面の言葉」にそろえる（置く物は Sticker、背景は Background、Sky は Sticker の置き場所だけ、上流は
  「From ＜ノードの名前＞」）。画面に ERP・Equirectangular・Perspective・Upstream と出さない。
- 入れる順番：ノードと状態の変更は、新しい UI への切り替えと同じ change で入れる（それまで古い UI と開発の環境を壊さない。完成まで
  main へは出さない）。

### Panorama モードの表示

- Panorama モードの Output の小窓と Camera タブは、Camera の位置から描いた ERP をその場で見せる（何かが変わったときだけ、小さな
  解像度で描き直す）。直近の実行の出力を見せる案は、実行するまで編集と食い違うのでやめた。ブラウザで ERP を描く部品は今は無く、
  新しい描画の経路になるので、最初に試作で重さを測り、オーナーの GPU でも確かめる。重すぎれば止めて相談する
  （`docs/threejs-spark-integration.md`）。

### 置く・選ぶ・動かす

- 物は一回のクリックで選び、ダブルクリックは回る中心にして向く（今のまま）。ComfyUI・Blender・Figma と同じく一回のクリックで選ぶ。
- 選んだ物の操作は、選んだ物の近くに浮くメニューではなく、ステージの下の中央に固定したバーに置く（位置が安定し、ギズモと重ならない。
  ペイントの道具と同じ場所を使い回す）。ギズモの切り替えのショートカットは 1 / 2 / 3（WASD / QE と重ならない。バーの並び順）。
- 入力から来た物の「Back to Initial」と上流の物の「Revert」は、一つの「元に戻す」にまとめる。
- Add で画像を選んだときだけ、読み込んだ後に Sky / World の二択を出す（ADR 0047 の「Add も画面の中心の光線で行き先を決める」を
  置き換える）。Add には狙う手段が無く、水平に見ていると画面の中心は空を向くので、光線で決めると黙って Sky になる。ドロップは
  指した点が意思を表すので、今のまま光線で決める。Add の 3D はいつも World で、前に何も無ければ `T` の真下の地面に置く。
- ドラッグ中の着く所の印は、落ち着いた黄の角のかぎ括弧と薄い塗りにし、ポインタの横に Sky / World のラベルを出す（ADR 0047 の「黄色の
  印」の形を置き換える）。同じアイコンを置いた後の印にも使う。

### インスペクタと Keyframe

- インスペクタの各行に Keyframe のポチを置き、その行の Lane だけに打つ・消す。行のポチ（全 Lane）だけでは、一つの値だけを変えずに
  「ここで止める」Keyframe を打てず、11 フレームで止めて 20 フレームへ動かす、のような基本の動きを作れない（プロの使い方に応えられ
  ない）。`docs/timeline-ui.md` の「インスペクタには Keyframe を打つボタンを置かない」と「ストップウォッチのような UI は作らない」を
  置き換える。グラフエディタは今も作らない。
- 値は欄そのものをドラッグして変える（Blender・DaVinci Resolve と同じく、カーソルを消す）。値が一つの行だけスライダーを置く。行ごとに
  既定値へ戻すボタンを置く（試してから戻れる道があると、初めての人が安心して触れる）。
- Keyframe を選んだときだけ、インスペクタの下端に Rive と同じ Easing のパネルを出す。曲線のグラフはいつも 1:1 で、上の領域が狭くなりすぎる
  ときはグラフを縮める。
- タイムラインの Keyframe は範囲で選べるようにする（アニメーションのソフトで普通の操作）。再生のループはスイッチで切り替える。前後の
  Keyframe へ飛ぶボタンは、物を選んでいればその物の Keyframe、いなければ表示している全部の物の Keyframe を数え、端で止まる。

### 見た目

- 色の土台は ComfyUI の役割の色に乗せ、ライトとダークは ComfyUI のテーマで自動で切り替える（オーナー：「ComfyUI のデザインは
  ダサいが、ある程度合わせないと浮く」）。灰の段は Geist の役目の分け方に倣う。
- フラット（影なし）。部品は完全に丸く、入れ物は一つの角丸。畳む・開く・Lock・Fullscreen は、状態をアイコンの形で示すなら押すたびに
  切り替わるボタンでよい（`docs/agents/ux-principles.md` に例外として書いた）。
- 色は意味のある一点にだけ使う（rauno.me の「同じものの中の違いが重要さを示す」）。機能ごとに色の点を付ける案は、意味が無かった。
- 書体は Plus Jakarta Sans を同梱する（今まで指定していたが読み込んでおらず、使う人のパソコンでは一度も表示されていなかった。
  オーナーが選んだ書体を実際に見せる）。ファイルを足すのは、大きさとライセンス（SIL OFL 1.1）を見せて承認を得てから。

## 考えた別案

| 案 | 選ばなかった理由 |
|---|---|
| 作業の段（置く／撮る／時間）ごとに画面を切り替える | 見る・置く・撮るは行き来する。視点で「モードを切り替えない」と決めたことと逆向き |
| Unwrap のタブを残す | 3D と平らな絵を同じ列に並べると、どちらにいるか分からなくなる。Camera タブ（すり合わせの途中では Frame タブと呼んだ）が出力として役目を引き継ぐ |
| 上の帯（ヘッダー）を置き、Undo / Redo やタブを載せる | ステージの面積が減る。載せるべき情報が無かった |
| 撮影のセクションをインスペクタの下に固定する | Easing のパネルが下端を使うので、選んだ物の欄がほとんど残らない。撮影のカードは選んだ物のカードの下に続けた |
| 撮る設定をすべてエディタに置き、ノードには結果だけを出す（P1） | `bg_color` と出力の大きさ（Resolution Selector と同じ形）はノードの上がよい（オーナー） |
| 出力の種類をノードの上のモードの切り替えにする | Camera の構図と撮り方が二か所に分かれる。いつもある Camera の性質として撮影のカードに置いた |
| Camera を `null` にできるまま（足す・消す） | 「Camera があるか分からない」「足したのに何も変わらない」「Camera モードなのに Camera が無い」の元 |
| Camera のボタンを無くし、撮影のカードのモードだけにする | カメラを足す操作は誰でも知っており、ボタンが無いと最初の一歩で迷う（オーナー） |
| Camera のボタンを「ここで撮る」（モードを変えない）にする | Panorama モードで押すとカメラの位置が変わるだけで、見た目にはほとんど何も起きない |
| `auto`（背景の細かさに合わせる）を残す、「背景に合わせる」ボタンを置く | 生成 AI に渡す大きさが背景しだいで変わる。背景が無いときは決め打ちの値になる |
| 背景の範囲を縦横比から自動で決める | わざと引き伸ばす使い方がある（オーナー） |
| 背景の範囲を角度（横何度 × 縦何度）で持つ | 使う人に数字を決めさせ、かえって分かりにくい。Unity と同じ二値で足りる |
| 出力の範囲の既定を「背景に合わせる」にする | 二つの設定をつなぐ規則が増える（オーナー「どんどん汚くなる」） |
| Camera タブ（当時は Frame タブ）のシャッターで Camera の全部の値に Keyframe を打つ | 行のポチと意味が重なる。値ごとのポチで一つの値だけを打てる |
| Camera タブ（当時は Frame タブ）で FOV / Lens / Roll を切り替えて一本のダイヤルで変える | 全部をいつも出しておく方が分かりやすい（オーナー） |
| Camera タブ（当時は Frame タブ）の操作をフレームの下の帯にまとめる | フレームの左・右・下に沿わせる方がカメラの UI らしい（オーナー） |
| 選択メニューを選んだ物の近くに浮かせる（今の形） | 位置が安定せず、ギズモと重なる |
| ギズモの切り替えを Unity の W / E / R にし、WASD を右ボタンを押している間だけにする | 右ボタンを押しながら移動する ComfyUI の使い手はいない（オーナー） |
| Blender の G / R / S | S が後ろへの移動とぶつかる |
| ダブルクリックで物を選ぶ（SuperSplat の形と聞いた。こちらでは確かめていない） | 一回のクリックで選ぶのが ComfyUI の当たり前。ダブルクリックは向く操作に使っている |
| 機能ごとに色を付ける（見る・撮る・時間・描く）、色の点 | 意味が無く、色を堂々と使いすぎる（オーナー） |
| 影で浮かせる（Material） | オーナーは影を嫌う。地の不透明さと 1px の線で足りる |
| ドロップの印をすみれ色の破線にする | 明るい空の上で沈む。破線より角のかぎ括弧の方が静か（オーナー） |
| 3D タブの Camera を、画面に向けた札（アイコン）で示す | 大きさが一定なので遠くても画面に残り、邪魔になる |
| 3D タブの Camera をカメラの模型で示す | 撮る向きと写る範囲が三角錐ほど読めない。次の候補に積む |
| 画像の側のレンズ（`curve`・`lens`）をインスペクタに出す | 往復が撮ったカメラの値を自動で入れ、描くときに戻す値で、使う人が決めるものではない |
| 背景を今までどおり上流優先にする（自分の背景は警告して使わない） | 直したパノラマで背景を差し替えられない。つないだものが黙って無視される。上流優先の理由は記録に無かった |
| Panorama モードの小窓と Camera タブに直近の実行の出力を出す | 実行するまで編集とずれる（オーナー） |
| 出る大きさを `io.ResolutionPreview` で見せる | `state_json` の比を読めない。比を文字列の widget にも持つと同じ値が二か所に住む。Node 2.0 でしか表示されない |
| 持ち上げた 3D も Sticker として刺す（土台の入口を持たない） | 「選べない Sticker」「地面の基準の Sticker」という例外が増え、データの変更も最も大きい。複数の Sticker が先に要る |
| 背景の入口がパノラマとその 3D の両方を受ける | 無限遠の Sky と奥行きのある World の区別とぶつかる |
| `scene` を一本の入口のまま、用語だけ直す | 刺すたびに Scene か土台かを判断することになり、迷いが残る |
| 撮り方のモードの名前を Standard・Photo・Perspective・Flat にする | Standard は意味が弱い、Photo は静止画に読める、Perspective は透視図法に聞こえる、Flat は聞き慣れない。Frame のままにし、タブを Camera にした |
| `sticker_state` を `sticker_pose`・`sticker_track`・`sticker_camera` にする | pose は時間を、track は時間が無いときを、camera も中身の一部しか言い表さない。state は汎用的で誤りではない（オーナー） |
| 上限 4096 のまま `megapixels` の最大を 8 にする | コアに合わせればよく、わざわざ小さくする必要がない（オーナー） |
| インスペクタのカードの順をタブで並べ替える（3D は Scene が上、Camera タブは Camera が上） | 規則がややこしい。インスペクタは今触っているものだけを映す形にした |
| 撮影（Camera）のカードをいつもインスペクタに置く | 3D タブは物を動かす場所で、いつもカメラが見えるのは変（オーナー）。Camera はいつもあり、Camera タブもある |
| 「原点に戻す」の専用のボタンを Position の行に置く | 位置と向きの両方を戻すので、行のリセットはその行だけ、の規則と食い違う。Rotation の行を足し、行のリセットで戻す |
| Camera タブで使えない部品を出さない | タブで部品の席が変わる。同じ席で無効にする（オーナー） |
| 視点の操作のつまみを右下にボタンと並べる | 右下に 6 つ並び窮屈。意味の違う物を場所で分ける（右の中央に縦。実機で邪魔なら戻す） |
| Panorama モードの Camera タブで、左の列の Camera のボタンを押せるようにし、上端に「Frame に切り替えて構図を作る」案内を出す | 分かりにくい。Frame への切り替えはインスペクタの Camera のカードの Mode でできる。初めての人には README で見せる（オーナー） |
| 撮り方の既定を Frame にする（見慣れたカメラの画面から始まる） | 出力が変わる（何もしないと 360° のパノラマが出る、というこのノードの芯が変わる）。一長一短で、既定は Panorama のまま（オーナー） |
| 直したパノラマで背景を差し替えたとき、上流の空の Sticker が見えていれば一行で知らせる | 焼き込んだかどうかはノードに分からない。要らない上流の Sticker を消すか、ペイントの行を隠せばよい（オーナー） |

## Consequences

- 一部を置き換える：ADR 0029 の「`camera` は `null`（無い）か Camera のオブジェクト」（いつも一台。`null` は既定の Camera）。
  ADR 0045 の「Camera を足す・消す…」「Camera が撮っていない（隠している）ときは原点」（Camera は消せず、隠しても撮る）。ADR 0047 の
  「Camera を選んでも `T` は動かさない」（3D タブでは Camera のまわりを回る）、「Add は画面の中心…同じ規則」（Add の画像は二択）、
  「着く所を黄色の印」（かぎ括弧と薄い塗り）。三つの Status に一行を足す。
- `docs/timeline-ui.md` の「インスペクタには Keyframe を打つボタンを置かない」「ストップウォッチのような UI は作らない」は、新しい UI
  では行ごとのポチに置き換わる（古い UI は今のまま）。
- 状態の形が変わる：`camera` がいつもあり、`camera.erp_range` が加わる。保存するテキストは既定の Camera を書かないので、今まで
  「Camera が無い」と保存した状態のテキストは変わらない。`coverage` 180 で Camera の無かった Studio は、出力が 180 から 360 に変わる
  （公開前の手元の状態だけで、オーナーが受け入れた。移す手順も特別な読み方も持たない）。
- 出力の長い辺の上限が 8192 になり、16 MP の出力のメモリと時間が増える（`docs/runtime-resources.md`）。
- ノードの入力と出力が変わる（`bg_media` → `background`、`bg_color` → `background_color`、`coverage` → `background_range`、3D の素材の
  `scene` → `world`、`scene` は `PANO_SCENE` だけ、`output_size` → `megapixels`・`multiple`、入力と出力の順。新しい Preview の `coverage` →
  `background_range`）。パラメータの形の変更で、Panorama Studio
  が公開前であることを理由に移す手順を持たない（AGENTS.md の Stop & ask。オーナーが承認）。
- 新しい UI の画面ができるまで、古い UI は今の規則のまま動く。古い UI の Camera の追加・削除、`coverage`、`output_size` に依存する
  コードは、切り替えのとき（ADR 0044 の「置き換えの進め方」）に、Panorama Studio の分だけ外す。
