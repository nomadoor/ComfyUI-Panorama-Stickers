# ADR 0039: `DA3_GEOMETRY` mono のエディタ用ファイルを深度のグリッドにする

## Status

Accepted（2026-10-10）

## Date

2026-10-10

---

## 背景

`DA3_GEOMETRY` mono（1920 × 1080、314 フレーム）を実機で実行すると、次のようになった。

- 実行に約 252 秒かかった。大半は、フレームごとのエディタ用の GLB（1 つ約 45〜50 MB）を書く時間だった。
- エディタの再生は約 5 fps だった。フレームごとに約 50 MB の GLB を取得してパースするためである。
- temp が約 13 GB になった。
- 60 フレームで測ると、エディタ用ファイルを書くときに全フレームを変換していた。最初のフレームの描画は、キャッシュから追い出されたフレーム 0 をもう一度変換した。`video` を読むと、ほかのフレームもすべて変換し直した。

## 決定

`DA3_GEOMETRY` mono のエディタ用ファイルを GLB にせず、フレームごとの float32 の深度のファイルと、全フレームで 1 つの色のプロキシの MP4 にする。エディタは、1 つの静的なグリッドを頂点シェーダーで深度から立ち上げて描く。形式は `docs/studio-node.md` の「`DA3_GEOMETRY` mono のエディタ用ファイル」、描き方は `docs/threejs-spark-integration.md` の「`DA3_GEOMETRY` mono の深度のグリッド」、残す画素の規則は `docs/render-contract.md` の「mono の残す画素」にある。

- 残す画素（`keep`）は、Python がコアの部品（`_da3_build_mask`・`depth_map_edge`）を組み立てて求める。コアの変換は呼ばない（使う人の決定 A）。test で、コアの変換が残す頂点と面と一致することを守る。
- `keep` は深度の値で表す。`keep` の外は 0 を書き、`keep` の画素は必ず 0 より大きい（`keep` が `depth > 0` を含むため）。マスクのファイルは持たない。使う人が決めたのは誰がマスクを作るかで、どう符号化するかではない。
- 色はプロキシの MP4 から取り、表示にだけ使う（使う人の承認）。
- 出力の描画は変えない（コアの変換のまま）。エディタ用ファイルと中身の箱が変換を呼ばなくなるので、描画は 1 回のパスで各フレームを 1 回だけ変換する。
- `extrinsics` を持つ mono の辞書は入口でエラーにする（深度のグリッドは `extrinsics` を掛けないため）。
- 範囲は DA3 mono だけ。multiview は GLB のまま。`MOGE_GEOMETRY` を同じ形式にすることと float16 の深度は、次の候補とする（float16 は劣化なので、使う人の承認が要る）。

## 考えた別案

| 案 | 選ばなかった理由 |
|---|---|
| GLB の書き出しだけを速くする | エディタは約 5 fps、temp は約 13 GB のまま |
| 生のバイナリのメッシュ | 1 フレーム約 50 MB のままで、約 10 fps |
| GLB を先読みする | 約 1.2 GB/s の読み込みが要り、できない |
| 止めたときだけ正確に出す | 実行の時間とディスクの量が直らない |
| xyz の点のマップ | 深度の 3 倍の帯域 |
| `MOGE_GEOMETRY` とまとめる | 変更が大きいので後にする |
| JS の CPU でメッシュを組む | 約 15〜20 fps（見積もり。未計測）。深度のグリッドが使えないときの予備の案 |
| 間引き | 使う人のデータを黙って劣化させるので、しない |
| `keep` をコアの変換の頂点の uv から戻す | 変換を 1 フレーム 1 回余分に呼ぶ。部品の組み立て（約 0.03 秒）で同じ画素になる |
| 1 ビットのマスクのファイルを別に持つ | 深度の `> 0` で同じことが表せ、ファイルが 2 倍になる |

## Consequences

- temp は、1080p × 314 フレームで約 2.6 GB と MP4 になる（GLB では約 13 GB）。4K の 314 フレームは約 10.4 GB で temp の上限（5 GiB）を超え、実行の後に古いフレームから消える。
- エディタは 1 フレーム約 8.3 MB を取得して R32F のテクスチャにし、ほかの要素と同じ上限（`SCENE_ITEM_BUDGET`、1.5 GiB）で持つ。WebGL2 が要る。テクスチャの一辺が GPU の `MAX_TEXTURE_SIZE` を超える要素（4K で 4096 未満の GPU）は読めない。
- エディタの色はプロキシから来るので、H.264 の誤差、4K の入力の縮み、再生中の ±1 フレームのずれがノードの出力との差になる（`docs/threejs-spark-integration.md` の「ノードの出力との差」）。
- 深度から位置への式は、JS の頂点シェーダーに写しを持つ。Python の test と、エディタと出力の一致の場面（`docs/render-contract.md` の「エディタとの一致（DA3 mono の場面）」）で守る。
- エディタ用ファイルの形式が変わるので、前の版のエディタはこの実行結果の `scene` を描かない。状態とポートは変えない。
