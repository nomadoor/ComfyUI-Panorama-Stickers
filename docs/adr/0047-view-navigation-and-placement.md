# ADR 0047: 一つの視点の動かし方と、新しく置く物の行き先

## Status

Accepted（2026-10-29）

## Date

2026-10-29

---

## 背景

ADR 0045 は視点を一つにし、「一つの視点の動かし方（ドラッグで向く方向、回る中心、ホイール、修飾キー）は、言葉では決めず
試作で触って決める」とした。ADR 0046 は地面の高さ `ground` を持ち、置く物を地面に置くとした。2026-10-14 から 10-29 まで、
試作の branch（`proto/single-viewpoint`。merge しない）で 21 回の試作をオーナーが触り、操作と置き方を決めた。この ADR は、
その決定と理由、試して捨てた案を残す。規則そのものは living spec `docs/space-and-view.md` が持つ。

参考にした既存のツール（どれも code は写していない。考え方を作り直した）：

- Blender（main session がソースで確かめた）：パンは `view3d_navigate.cc` の `viewmove_apply` と `ED_view3d_win_to_delta` で、
  ビューの中心の深さの 1 画素を 2 · d · tan(画角 ÷ 2) ÷ W として動かす。ホイールは `view3d_navigate_view_zoom.cc` の一段 1.2 で、
  ビューの中心までの距離を 1.2 倍か 1 ÷ 1.2 倍にする。設定の Auto Depth（掴む深さをポインタの下の点にする）と Zoom to Mouse
  Position（ポインタの下の点へズームする）は任意。Orbit Around Selection も任意の設定（公式マニュアル）。
- SuperSplat（エディタ）：カメラを焦点・方位・仰角・距離で持ち、回り込みは 0.3°/px。
- SuperSplat Viewer（`src/camera-manager.ts`・`cameras/camera-utils.ts`）：回転・移動・ズームに damping 0.95 を掛ける。最初の視点が
  場面の箱の外なら orbit、中なら walk / fly で始める。
- Unity（公式マニュアル）：Alt + 左ドラッグで今のピボットのまわりを回り、F で選んだ物に合わせる。
- Blender の Images as Planes（公式マニュアル 3.3）：3D カーソルに置き、向きはカメラに向けるなどを選べ、大きさは高さで指定する
  （既定 1）。

## 決定

### 割り当て

- 何もないところの左ドラッグと、右ドラッグ（どこでも）は、その場の見回し。右ドラッグは物に触らない。物に触るのは Alt なしの
  左ボタンだけ。
- 中ボタンのドラッグはパン。Alt + 左・右ドラッグは、物やギズモの上でもオービット。Alt + 中ボタンは前後のジョイスティック
  （押した点からのずれが速さ）。ホイールは前後。WASD / QE は任意の近道。
- Alt は近道で、押している間はカーソルを変えて示し、文字では示さない。押している間は物とギズモのホバーを強調しない。
- 同じ操作をキーなしでできるように、右下に視点の操作の部品（球・手・矢印）を置く。どれもドラッグするつまみで、押すたびに
  切り替わるボタンではない。tooltip で Alt の割り当ても案内する。
- カーソルはステージでは見回しの形、触れる物の上で物のカーソル。
- Frame 表示（Camera から見る）も同じ割り当てで、動くのが Camera になる。roll はノブだけで変える。
- ComfyUI の設定「3D view controls」のプリセットは、Panorama Studio と Preview では使わない。

理由：オーナーは見回しを主に使い、オービットは近道で足りる。左右のドラッグの手触りが違うと迷う。Frame 表示だけ Alt が roll
だと、同じ手が表示で違う意味になる。

### 注視点 `T` を持ち続ける

- 視点は位置・向きと、持ち続ける一つの注視点 `T` を持つ（SuperSplat の焦点、Blender のビューの中心と同じ考え）。`T` は画面の
  中心の線の上で付いて動き、黙って探し直さない。決め直すのは、ダブルクリック、Frame Selected、Reset View と、選んだ物が
  あるときのオービットの始まりだけ。Camera を選んでも `T` は動かさない。
- `T` の印は画面に出さない。
- 開いたとき・Reset View の `T` は、画面の中心の線が最初に当たる点（内容か地面。世界の境界の中）、無ければ 5 `E` 先。
- ダブルクリックは World の画像の板にも当たる（ほかの当たりは板を素通りする）。見えている物に焦点を合わせる操作だからである。

理由：押すたびに回る中心をポインタの下や画面の中心で探し直すと、中心までの距離（＝回り込みで動く量）が毎回変わり、
振り回される。押した瞬間のポインタの下を中心にするのは、中心が想定の場所に無く直感的でなかった。印を出しても、回っている
中心には見えなかった。Camera は足すと今の視点の位置に置かれて選ばれるので、選択で `T` を Camera に移すと距離が 0 に近づき、
パンがほとんど効かなくなった。

### 直接の操作は 1 対 1、なめらかさは一回で決まる操作だけ

- ドラッグ・ジョイスティック・キーはその場で 1 対 1 に当て、エディタでは遅れも慣性も付けない。
- ホイールの一段、ダブルクリックの向き直し、Frame Selected、Reset View だけを 0.4 秒の ease-out で動かす。

理由：ドラッグ中に追従の遅れ（SuperSplat の減衰）を掛けると、指と画面がずれ、移動量と回転量が合わなくなった。見回しの慣性は
パノラマとしては好まれたが、3D のツールでは一般的でない。

### パン・ホイール・前後の量は Blender の式、上限は目の高さ `E` の絶対の量

- パン：押したときにポインタの下の点（内容か地面。空なら `T`）を掴み、その視線の軸の深さ `z` で 1 画素 ＝ 2 · `z` · tan(横の画角 ÷ 2)
  ÷ W として動かし、掴んだ点をポインタの下に留める（Blender の Auto Depth のときと同じ考え）。
- ホイール：ポインタの下の点 `G` を中心に、視点と `T` を 1 ÷ 1.2 倍か 1.2 倍に縮尺する（Blender の一段 1.2 と Zoom to Mouse
  Position。空なら `G` ＝ `T`）。遠すぎる当たりと境界の外の当たりは空として扱い、比は一段の向きを越えず、`T` までの距離を上下限
  の中に保つ。
- ジョイスティックと WASD / QE は、1 秒に `T` までの距離 `d` を基準に進む。
- 上限と置く大きさは、目の高さ `E` ＝ `|ground|` の倍数の絶対の量で持ち、内容の大きさでは変えない：世界の境界（原点中心、
  30 `E`。Camera と内容を含むように広げる）、`T` の距離の範囲（0.005 `E`〜30 `E`）、グリッド、置く画像の高さ。

理由：

- 内容の大きさで速さを決めると、物を置いたり内容が読み込まれたりするたびに全部の速さが変わった。オーナー：「そんなバカみたいな
  デカいものも無いでしょう」。そこで一度、すべての量を `E` の絶対の量にした（試作 13 回目）。
- しかし絶対の量（ホイール一段 0.16、パンの深さ 1.2）は、見ている物と手が合わない：遠くを見ると進まず、Blender と比べて小さすぎた。
  `T` を持ち続けるので、量を `T` までの距離に比例させても毎回ぶれない。パン・ホイール・前後の量について絶対の量をやめた。
- パンを `T` の深さで動かすと、`T` が空中 8 の先にあるとき、手前の地面の点が指の 2.7〜3.6 倍動いた（37px のドラッグで 132px）。
  掴んだ点の深さにすると、ずれは無くなった。
- ホイールの比を制限しないと、遠い当たりで向きが逆になったり視点が跳んだりした（試作 21 回目で直した）。
- 世界の境界を内容の中心に置くと、原点から遠い内容のとき、視点が最初から境界の外にいた。

### Sky だけの場面

- Sky だけの場面も普通に動ける。「Sky only」の知らせは出さない。境界で止まったときだけ一行の知らせを出す。

理由：地面のグリッドが見えている今は、動いても何も変わらないわけではない。

### Add とドロップの行き先

- ツールバーの Add は一つ（Add to World は無くす）。Add は画面の中心、ドロップはドロップした点を通る光線で、同じ規則で決める。
- 光線の最初の当たり（3D の物か地面）が世界の境界の中にあれば World、無いか境界の外なら、画像は Sky の Sticker になる。3D ファイル
  は当たりが無ければ境界の中の最も遠い地面に置く。
- ファイルをドラッグしている間、着く所を黄色の印で見せ、Sky か World かを離す前に分からせる。
- World の画像の板は着く面にしない（素通りして奥の 3D の物か地面へ）。
- World に置く画像は、高さ `E`・幅は縦横比からの決まった大きさで、着く点の真下の地面に、視点の方を水平に向けて立てる。浮かせない。
- Reset View は開いたときの視点と同じ（位置と yaw は Camera か原点、pitch は水平）。

理由：

- 行き先が見ている所で決まり、離す前に見えれば、Sky か World かを使う人に選ばせなくてよい（ADR 0045 の、往復が行き先を決める）。
- ドロップの届く距離を 500 単位まで取ると、遠くへ落とした物が World の遠い点に置かれた。遠くへのドロップは Sky に置きたい意思
  とみる。
- 画像の大きさを「画面上 30°」（Sky の Sticker の規則）で決めると、World では置いた距離で大きさが変わり、錯視になった。
- 画像の板を当たりに数えると、次の画像が板の途中の高さに当たって浮いた。当たった点に立てるだけでも、物の上に当たると浮いた。

### Preview のウィンドウ

- 割り当てはエディタと同じ。見るための場所なので、手触りはなめらかにし、減衰と離したときの慣性を付ける（SuperSplat Viewer の
  damping 0.95 と同じ考え）。IMAGE・VIDEO も同じ。地面のグリッドは既定で隠し、見る人が決まった席のスイッチ（on / off）で出す。World の内容が無くても自動では
  出さず、グリッドを隠したまま絵が変わらない移動をしても知らせない。

理由：Preview は編集ではなく見るための場所なので、既定では編集の目印を出さずに絵だけを見せる（SuperSplat Viewer が
エディタと別の見るための道具であるのと同じ考え）。World の内容が無い Preview（IMAGE・VIDEO、Sky だけの Scene）では、
グリッドを隠していると移動しても絵が変わらず、`docs/agents/ux-principles.md` の「効かない操作を黙って無視しない」と ADR 0045 の
「短く知らせる」とぶつかる。スイッチがいつも見えていて、出せば動きが分かるので、このずれは受け入れる。

### 原点の印

- 原点の真下の地面に小さな輪を描き、「ERP origin」の文字は出さない（ADR 0045 が spec に預けた、印を残すかと名前）。

## まだ決めていないこと

- Camera を Camera の位置以外から見ているときの、選んだときの見た目（ADR 0045 が spec に預けたもの）。
- そのほかは `docs/space-and-view.md` の「まだ決めていないこと」。

## 考えた別案

| 案 | 選ばなかった理由 |
|---|---|
| 3D view controls のプリセット（Default・Blender-like・Unity-like）を残す、コアの Load3D の割り当てに合わせる | どのプリセットにも主の操作の見回しが無い。Load3D は右ドラッグが移動、中ボタンが前後で、見回しを置けない |
| 回る中心をオービットの押下のたびに、ポインタの下の点で決める | 中心が想定の場所に無く、直感的でない。距離が毎回変わり、回る量が変わる |
| 回る中心を押下のたびに、画面の中心の線の最初の当たりで決める | 距離が毎回変わり、振り回される |
| `T` の印をいつも出す | 印があっても、回っている中心に見えなかった |
| SuperSplat のように、ドラッグ中にも追従の遅れ（減衰 0.2 秒）を掛ける | 指と画面がずれ、移動量と回転量が合わなくなった |
| 見回しに慣性を付ける（今の 3DoF と同じ） | 3D のツールでは一般的でない（Preview では付ける） |
| 速さと上限を内容の大きさ（外接球の半径）から決める | 物を置く・読み込むたびに全部の速さが変わる |
| パン・ホイール・前後の量を `E` の絶対の量にする | 見ている物と手が合わない。遠くでは進まず、Blender より小さすぎた |
| パンを `T` の深さで動かす（Blender の Auto Depth を切ったとき） | 手前の地面が指の数倍動いた |
| ホイールでいつもポインタの方へ一定の割合だけ進む、最小の一歩を足す | 進んだり進まなかったりした。規則が重なり、予測できない |
| ホイールで画角を変える（Alt + ホイール。試作の候補 B） | 試作で比べ、前後に進むだけの候補 A を選んだ |
| 世界の境界を内容の中心に置く | 原点から遠い内容のとき、視点が最初から境界の外にいた |
| Sky だけの場面で「Sky only」と知らせる | グリッドが動いて見えるので誤り |
| Preview で、World の内容が無いときはグリッドを自動で出す、または隠している間の移動を知らせる | 出し入れを見る人が決めるスイッチ一つにする。スイッチがいつも見えている |
| 物の上の Alt + 左を物の操作にする | 物の上では Alt + 左で回れず、Alt + ドラッグの意味が場所で変わった |
| Frame 表示だけ Alt + 左を roll にする（今の割り当て） | 同じ手が表示で違う意味になる |
| Add と Add to World を分ける、ドロップの画像はいつも Sky | 入口で行き先が違った（ADR 0045 の背景） |
| ドロップの届く距離を 500 単位まで取る | 遠くへのドロップが World の遠い点に着いた |
| World の画像を画面上 30° の大きさで置く | World では距離で大きさが変わり、錯視になった |
| World の画像を当たった点や目の高さに立てる（ADR 0046） | 画像の板や物に当たって浮いた |
| 画像の板をドロップの着く面にする | 次の画像が板の途中の高さに浮いた |
| Camera を選ぶと `T` を Camera に移す（視点から近いときだけ移さない規則も試した） | Camera は視点の位置に足されるので距離が 0 に近づき、パンが効かなかった。距離による例外はやめ、Camera はいつも数えないことにした |

## Consequences

- 規則の owner は living spec `docs/space-and-view.md`（`docs/agents/workflow.md` の Living specs の表）。新しい UI に切り替えるまで、
  古い UI の視点の規則は `docs/editor-interaction.md`・`docs/preview-node.md`・`docs/threejs-spark-integration.md` が持つ。
- 一部を置き換える：ADR 0045 の「そこで前に進んでも見た目が変わらない操作は、黙って無視せず短く知らせる」（Sky だけの場面では
  知らせない）と、「足す入口（Add to World とドロップの違い）は…決め直す（未決）」と「ERP origin の印は…spec で決める」（この
  ADR で決めた）。ADR 0046 の「World に置く画像の板は、今のまま正面の目の高さに、視点に向けて立てて置く」、「1.6 は…規則が
  この数に依存することはない」（上限と置く大きさは `E` の倍数）、エディタの Add とドロップで「新しく置く 3D の物は、正面の地面の
  上に置く」（光線が当たった所に置く）。両方の Status に一行を足す。
- ノードが置く 3D の `port` の Sticker には画面の光線が無いので、ADR 0046 の地面の上に収めて置く規則のままになる。ADR 0046 の
  「入口によって置き場所の規則を二つにしない」とのずれは、`docs/space-and-view.md` の「まだ決めていないこと」に残す。
- `docs/agents/ux-principles.md` の「速度は Scene の尺度に合う単位で持ち」は、`T` までの距離に比例する量と目の高さの上限で
  満たす形になる。
- CONTEXT.md の用語（注視点 `T`、世界の境界、目の高さ `E`、Viewport camera の言い直し）は、別に承認を得て足す。
