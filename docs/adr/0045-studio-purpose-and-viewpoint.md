# ADR 0045: Panorama Studio の目的は空間の往復であり、視点は一つにする

## Status

Accepted（2026-10-14）

## Date

2026-10-14

---

## 背景

UI の段（ADR 0044）に入るにあたり、オーナーと「このノードは何のためのものか」から決め直した。今の UI は、パノラマの絵を作る道具だった頃の
考え（原点に立って見回す 3DoF、Sky、ERP origin）と、3D の空間に物を置いて撮る道具になった今の考え（6DoF、World、Camera）を、
3DoF | 6DoF の切り替え一つで行き来させている。切り替え一つで、立ち位置・見ているもの・触っているものが一緒に変わるので、
使う人はどこにいて何を触っているのかを見失う。実機で出た問題（少し 6DoF で動くと足したものが空間のものになる気がする、
6DoF で Camera を足して 3DoF に戻ると Camera の枠が画面を埋めて操作できない、Add to World とドロップで行き先が違う）は、
ここから来ている。

## 決定

### 目的（オーナーの言葉から）

- 主役は 3D の空間である。パノラマはこのノードの出発点だが、空間を作る前処理の位置にある。
- 扱う空間は、メッシュ・3DGS・4DGS のような、既存の 3D 表現で持てる明示的な世界である。内部に世界を持ちリアルタイムの動画で出す
  world モデルは扱わない（その出力の動画は素材として受けられる）。操作に応じて変わるインタラクティブな世界も扱わない。
- このノードは、その空間のプレビュー・探索・編集の UI である。
- 編集の本質は**往復**である：空間に入り、崩れている所・変えたい所をくり抜き、外のモデルで直し、元の空間に戻す。パノラマの頃の
  「撮る → 外で直す → 戻す」と同じである。3D アセットを自由に置けるのは、その応用（くり抜いた元の無い戻し）にすぎない。
- 戻す先（向き・位置・縮尺、Sky か World か）は、往復が決める。使う人に選ばせることを前提にしない。

### Camera と Box は別のもの

| | Camera | Box（くり抜き） |
|---|---|---|
| すること | 視点から撮る（2D に落とす） | 空間の一部を囲んで取り出す（3D のまま） |
| 往復が成り立つ範囲 | 無限遠の層（背景・Sky）だけ。World の物は 2D に落ちるので、深度で持ち上げても見えている面だけになる | 空間のどこでも |
| 役目 | 出力を撮る（下流のモデルへの下書き）と、Sky の往復 | 3D の往復 |

Box は今は作らない。くり抜いた 3D をまともに直す手段が、今はまだ無いためである。UI の設計では Box の入口の席を取り、後から足しても
UI を継ぎ足しにしない。

### 視点は一つにする

- 3DoF | 6DoF の切り替えを無くす。Panorama Studio のエディタも、新しい Preview のウィンドウも同じ。視点はいつも空間を自由に動ける。
  背景・Sky の Sticker（ADR 0023）とペイント（`docs/threejs-spark-integration.md` の「空間の表示」）は無限遠の層なので、どこに立っていても
  同じ方向に見え、方向で触れる。今のコードでも、Sky の層は回転だけで描き、Sky の Sticker の選択・移動・拡大とペイントは向きから求めて
  いるので、原点の外からそのまま触れる。
- World の内容が無い場面（Sky だけ）も、同じ操作で動く。Preview のウィンドウで IMAGE・VIDEO を見るときも同じ操作になる（今の「見回しと
  ホイールで画角」だけの見方はやめる）。モードを内容で切り替えない。そこで前に進んでも見た目が変わらない操作は、
  黙って無視せず短く知らせる。
- Camera を足す・消す・隠す・Undo しても、視点は動かさない（今の「3DoF の立ち位置が Camera に付いて動く」はやめる）。ただし Frame 表示
  （視点が Camera そのもの）で Camera を消したときは、今のまま Camera が見ていた視点から Panorama 表示に戻る。
- エディタを開いたときは、同じページで前回の視点を覚えていればそこから、無ければ出力の視点（Camera があれば Camera の位置と向き、
  無ければ原点）から始める。Camera が撮っていない（隠している）ときは原点。
- Sky の物と World の物は、選んだときの見た目で見分ける（Sky は空に貼った枠と取っ手、World は板も 3D もギズモ）。選んだときに見える
  装飾は足してよい。行にはアイコンを付ける。動かさないと分からない形にはしない（動かすと編集になり、Lane に Keyframe があれば
  Keyframe が打たれるため）。
- Camera の選んだときの見た目は「空間と視点」の spec で決める。条件：Camera の位置から見たときにだけ正しい、方向で描く枠（今の
  Panorama 表示の枠と周りの暗がり）を、ほかの場所から見ているときに出さない。これが「枠が画面を埋める」の仕組みである。
- 物が重なって見えるときは、手前の選べる物を選ぶ（選んでいる物の取っ手は先に当たる。`scene` の中身は選べないので、その奥の物になる。
  今の順のまま）。後ろの物は、視点を動かすか行から選ぶ。
- 一つの視点の動かし方（ドラッグで向く方向、回る中心、ホイール、修飾キー）は、言葉では決めず試作で触って決める。土台は今の 6DoF の
  操作とプリセット（`docs/editor-interaction.md` の「6DoF の操作」）。比べる候補の一つはホイールで、A「いつも前へ進む、ビューポートの
  画角は固定」と B「前へ進む、Alt + ホイールで画角」。3DoF を無くすとその場で見回す操作（慣性つき）が Default のプリセットから
  無くなるので、見回しをどの操作に置くかも比べる。試作の場面には、Sky だけの場面と、Sky の Sticker のドラッグを入れる。

## 考えた別案

| 案 | 選ばなかった理由 |
|---|---|
| 3DoF | 6DoF を残し、今どちらにいるかを見せる | 見せ方を直しても、切り替え一つで立ち位置・見ているもの・触るものが変わる形は残る |
| 足すものの行き先を今の視点のモードで決める | 少し動いただけで行き先が変わる。オーナーが最も避けたい形 |
| 見分けを触ったときの動きで分からせる | 動かすと編集になり、Keyframe が打たれることもある（オーナー） |
| 重なったら同じ所のクリックで奥へ移る | 見た目に手がかりの無い動きで、別の物を動かして Keyframe を打つ恐れがある |
| Camera を 3D の往復の道具として見せる | 6DoF では 2D に落ちるので往復が正直に成り立たない（オーナー） |
| Box を先に作る | くり抜いた 3D を直す手段がまだ無い |
| World の内容が無いときだけ今の 3DoF の操作にする | 内容で操作の意味が変わる。物を一つ置いた途端にホイールやドラッグの意味が変わる |

## Consequences

- 3DoF・6DoF を前提にした記述を、新しい UI の「空間と視点」の spec で書き直す：`docs/editor-interaction.md`（「視点の操作」、Reset View、
  3DoF に戻る遷移、:157 の Camera の位置に立つ規則、:176-184 の Camera の出入りと視点）、`docs/preview-node.md`（「`PANO_SCENE` を見る」、
  大きなウィンドウの右下の群）、`docs/threejs-spark-integration.md`（空間の表示の条件）、`docs/editor-architecture.md`、`docs/timeline-ui.md`、
  `docs/agents/ux-principles.md`（固有の言葉の例の 3DoF と 6DoF）。`CONTEXT.md` の Viewport camera（見回すための視点）は用語の変更として
  別に承認を得る。
- 新旧が並ぶ間（ADR 0044）、新しい UI は下の部品の視点のモードを `6dof` に固定して使い、下の部品の振る舞いは変えない。モードの code
  （`pano_space.js` の `spaceModeView`・`switchSpaceMode`、`pano_space.js` の `spaceModeWithContent`、`pano_view_transition.js` の `spaceModeChoice`・`shownSpaceMode`、`pano_view_memory.js` のモードの検査、
  `floatingRightState` のモード）は、切り替えのときに古い UI と一緒に消す。旧ノードには空間の表示が無いので影響しない。
- 足す入口（Add to World とドロップの違い）は、往復が行き先を決める原則に合わせて決め直す（未決）。ERP origin の印は、Camera が無いときの
  出力の視点の印として、残すかどうかと名前を spec で決める。
- 一部を補う：ADR 0038 の物差し（「撮る（将来は 3D の空間を切り抜く）」）は、この ADR の Camera と Box の分け方で細かくする。ADR 0041 の
  「IMAGE・VIDEO は 3DoF、`PANO_SCENE` は 6DoF」は、使う人が切り替えるモードではなく「見回すだけか、動けるか」の違いとして読む。
  両方の Status に一行を足す。
- ADR 0044 の保留を解く：ノードは一つのまま組み直す。
