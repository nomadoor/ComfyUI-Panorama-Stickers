# ADR 0021: Cutout Frame タブ — クロップビューとしての座標契約

## Status

Active

## Date

2026-08-11

## Supersedes

- ADR 0017 のうち、Frame タブを「独立した pasted rectangle」として扱う前提
- `docs/Panorama Paint Rebuild2.md` の「frame view は `FRAME_LOCAL(frameId)` を編集する」という記述
  （フロント・バックエンドとも既に `ERP_GLOBAL` のみを描画しており、記述が実装と乖離していた）

---

## 背景と問題

Frame タブは「別キャンバスに貼り付けられた切り抜き画像」として実装されていた。

- `editor.frameView.panX / panY / zoom` が presentation 専用の pan/zoom を持つ
- ゲート（出力枠）矩形を先に決め、そこから投影スケールを逆算する
- ゲート外は単色の黒で、シーンの文脈が失われる

ここから次の症状が連鎖的に発生した。

1. アスペクト比を変えると背景（ERP）が勝手にズームする
2. ズームすると外周に黒い帯が出て、時間経過で濃くなる
3. 縦横切り替えで背景が大きく飛ぶ
4. 1:1 のときゲートが不必要に小さい
5. レイアウト測定のたびに縮尺がじりじり縮む

---

## 根本原因

**presentation scale・ゲートサイズ・FOV の3つは独立ではない。**

```text
presentation scale f = ゲートの画面サイズ / (2 · tan(FOV/2))
```

「ゲート内部＝出力そのもの」である以上この関係は動かせず、2つ決めれば3つ目は決まる。

旧実装は**ゲートサイズと FOV を決めて f を従属させて**いた。
その結果、アスペクトを変えるたびに f が動き、それが「背景のズーム」として見えていた。

---

## 決定

### D1. 権威の向き

**`f` を固定し、FOV を導出する。**

- ゲートは safe rect に収まる、そのアスペクトの**最大矩形**
- FOV はゲートと `f` から逆算して shot に書き戻す

```text
gate  = aspectFit(safeRect, ratio)
hFOV  = 2·atan(gate.w / 2f)
vFOV  = 2·atan(gate.h / 2f)
```

取り込む立体角は保存されない。**これは意図的である。**
Frame タブはクロップを構図するための画面であり、面積の絶対値を保つ場ではない。

この結果、次がすべて同時に成立する。

| | |
|---|---|
| 横長アスペクト | 幅いっぱい（上下に余白） |
| 縦長アスペクト | 高さいっぱい（左右に余白） |
| アスペクト変更・縦横切り替え | **背景は 1px も動かない** |
| 往復 | ゲート・FOV とも厳密に元へ戻る |

### D2. `f` を動かすのはホイールとリサイズだけ

- **ホイール** = カメラズーム。両 tangent を一様スケールすると `fitFocalPx` が逆比例で動くため、
  **ゲートは画面上で固定されたまま ERP がズームする**。補正コードは不要
- **リサイズ / UI レイアウト変化** = `f` は safe rect から再導出
- **アスペクト・縦横切り替え・ドラッグ** = `f` は不変

`f` は保存しない。`fitFocalPx(safeRect, shot)` という純関数である。
保存された presentation scale は、陳腐化・ラチェット・ドリフトの温床になる。

### D3. 縦横切り替えは「アスペクト比の反転」であり、FOV の入れ替えではない

`hFOV ↔ vFOV` の交換は立体角を保存するが、転置された横長フレームはビューポートより高くなり、
収めるために全体を縮小するしかない。アスペクト比を反転させて D1 の規則を通すだけでよい。

### D4. safe rect は shot に依存してはならない

ゲートの縮尺は safe rect から導出される。したがって safe rect の測定対象に
shot 依存のサイズを持つ要素が入ると、

```text
shot → レイアウト → safe rect → f → 背景の縮尺
```

というフィードバックループが閉じる。

- `.pano-floating-right`（cutout カメラプレビューを含む。箱の縦横比が shot に追従する）は
  **実測せず固定値で予約**する
- カメラプレビューは Frame タブでは非表示（ゲート内部が出力そのものなので冗長）

### D5. コンテキスト描画はゲートに依存させない

ゲート外もキャンバス全面に同一投影で描く。描画範囲の上限は**絶対画角のみ**
（矩形投影は 90° 付近で破綻するため 85° で打ち切り、外側は中立背景）。

ゲートサイズを基準に描画範囲を絞ると、ゲートが小さいときに未描画の帯が残る。
またフレーム先頭でキャンバスを不透明に塗り直すこと。塗り直さないと passepartout の
半透明黒が毎フレーム累積し、外周が黒へ収束する。

### D6. Frame タブはカメラ／クロップ専用ビュー

- キャンバス上のオブジェクト選択 UI・セレクションメニューを出さない
- 左ドラッグ（cursor ツール時）と中ドラッグはカメラ操作
- Inspector は active shot にバインドするが、`state.active.selected_shot_id` は
  ユーザーの明示操作なしに書かない（タブ切り替えで保存状態を変えない）

### D7. モーダル寸法は相対値

`width: max(720px, 80vw)` / `height: max(520px, 82vh)`。
絶対値の上限を置くと、画面が広いときにステージが不足側に張り付き、
アスペクトごとの律速軸が入れ替わってゲートが不安定になる。

---

## 座標契約

```text
World/ERP direction
  → shot camera basis (right, up, forward, roll 込み)
  → film-plane tangent 座標
  → canvas 座標 (× f, ゲート中心基準)
```

逆変換は同じ経路を逆にたどる。ゲート内は `|X| ≤ tanX, |Y| ≤ tanY` が出力範囲。

ドラッグは screen delta を film tangent に変換し、**roll を打ち消してから** yaw/pitch に分解する。
yaw はワールド上軸まわりの角度なので `1/cos(pitch)` の補正が要る（極付近は 0.25 で床を張る）。

---

## 永続データへの影響

- ノード ID・ポート・パラメータ名は不変。バックエンドは無改修
- 権威は既存の `(hFOV_deg, vFOV_deg)` のまま。`aspect_id` は UI 意図ラベル
- ロード時に既存の FOV ペアを正規化しない
- `editor.frameView.panX/panY/zoom` は transient で保存されていなかったため、単純削除
- 未知／レガシーのストローク（`FRAME_LOCAL` を含む）は JSON ラウンドトリップで保持する。
  新たなレンダラやエディタは追加しない

---

## やってはいけないこと

1. ゲートの幅・高さを**軸ごとに独立してクランプ**する（アスペクトが崩れ、コンテキストが伸びる）
2. `f` をホイール以外の操作で更新する（背景が動く）
3. `f` を保存してレイアウトキーでメモ化する（陳腐化・ラチェット）
4. `getFrameViewRect()` の中で DOM を測る（毎フレームの強制同期レイアウト）
5. レイアウト制約を満たすために shot の FOV を書き換える
   — ただし D1 の「`f` 固定で FOV を導出する」は例外であり、これが唯一の正しい書き換え経路
6. safe rect の測定に shot 依存要素を入れる
7. presentation の pan/zoom オフセットを再導入する

---

## 成功条件

- アスペクト・縦横切り替えで `f` が完全に不変
- 横長は幅いっぱい、縦長は高さいっぱい
- ホイールでゲートの画面サイズが不変、ERP がズーム
- 往復操作でゲート・FOV が厳密復元
- タブ切り替え・モーダル開閉で保存状態が変化しない

---

## Consequences

- 立体角は保存されない。縦横切り替えでクロップの実面積は縮む
- ステージが 16:9 より縦長のとき、横長アスペクトは幅律速になり上下に余白が出る（幾何学的必然）
- カスタムアスペクトが 16:9 より横長の場合のみ、`f` が現在のアスペクトに依存する
- Panorama タブからのアスペクト編集は safe rect が無いため、vFOV 保持の導出にフォールバックする

### Frame から Panorama へ戻るときの視点

タブ切り替えでは Panorama の yaw / pitch / FOV を変更しない。何も編集せずに
Panorama → Frame → Panorama と往復した場合、Panorama の見え方は完全に維持される。

フレームが画面外にあることは passepartout の全面減光で判別でき、復帰には既存の
`Look At Frame` を使える。そのため、自動的な視点補正や同等機能の別 UI は追加しない。

### Frame view の Roll 直接操作

Roll の主操作は Frame 固有の右レールに常設する目盛り付きノブとする。画像上には
常設ハンドルや不可視の操作ゾーンを置かない。ノブ以外の左ドラッグは、ゲート内外を
問わず yaw / pitch のまま維持する。熟練者向けには Alt + 左ドラッグでも Roll でき、
Alt 押下中はノブの強調と回転カーソルで入口を明示する。

ノブは既存のアイコンボタンと同じ箱の中にダイヤルを収める。ドラッグの入口はノブだが、
角度差は小さなノブではなくゲート中心に対するポインタ角から求める。したがって画像上で
直接 Roll していたときと同じ操作スケールを維持する。

ノブのダブルクリックは 0° へ戻す。ドラッグ中だけゲート内に水平ガイドと回転グリッドを
表示し、角度値は Vue の共通 tooltip を水平軸上に表示する。右レールの外寸は変えず、
Frame safe rect を縮めない。レールの強調色はフレーム枠と同じ黄色とする。

Roll は既存の `shot.roll_deg` だけをdraft更新し、pointer-upで変更がある場合に一度だけ
履歴とwidget stateへcommitする。Esc / pointer cancel / capture喪失時は開始値へ戻す。
通常時は0°の±1°に吸着し、Shiftは15°刻み、ノブ操作中のAltは0°吸着を無効化する。
Alt + canvas で開始した操作では、起動キーとの衝突を避けて0°吸着を維持する。
Panorama側のオブジェクト回転（45°刻み）は用途が異なるため変更しない。

## 検証

純関数を `web_src/pano_cutout_view_math.js` に切り出し、`node --test` で固定した。
特に**ビューポート幅を掃引する**テストを必須とする。単一寸法での確認では、
律速軸の入れ替わりを見逃す（実際に見逃してリグレッションを繰り返した）。
