# ADR 0066: control は選択で出たり消えたりしない

## Status

Proposed（2026-11-17）

## Date

2026-11-17

---

## 背景

動きの画面を決める途中で、軌道の点を選んだときだけ下の中央のバーに道具が増える形、Keyframe を 3 つ以上選んだときだけ Simplify のボタンが出る形、ボタンの上に小さな窓が開く形を試した。持ち主はどれも採らなかった：「突然ボタンが現れる、という UI がそもそも良くない」「ずっと表示されているが、押せない。条件がそろったときだけ押せる。そうすべき」（2026-11-16）。

今の決まり（`docs/agents/ux-principles.md`）には「別の control が出たり消えたりしても、control の位置を動かさない」「群の一員は隠さずに無効にする」があったが、選択に合わせて control そのものを出し入れすることは、決めていなかった。

## 決定

- control（ボタン、スライダー、切り替え）は、選択に合わせて出したり消したりしない。いつも同じ場所に出しておき、使えないときは隠さずに無効にして、理由を tooltip で示す。
- 例外は二つ。
  - Easing のパネルは、Keyframe を選んだときだけ出してよい。Keyframe を使わない静止画の作業では、丸ごと使わない部品だからである（持ち主：「静止画の場合は丸々使わない機能だ」）。
  - ある操作のすぐ後に、その結果を調整するための control は、その操作のボタンの隣に、調整している間だけ出してよい（Simplify のスライダー）。場所は先に取り、ほかの control を動かさない。小さな窓にはしない。
- オンかオフかだけのスイッチは、一つのボタンを押すたびに切り替えてよい。いくつかの状態から一つを選ぶものは、全部を並べて見せ、今の一つを点ける。
- ステージやタイムラインの上に重ねる表示（軌道の線、ハンドル、対象の帯）は control ではなく、状況で出し入れしてよい。選んだ物の種類で中身が決まるもの（下の中央のバー、インスペクタのカード）は、今までどおり種類で変わる。

規則は `docs/agents/ux-principles.md` が持つ。

## Consequences

- 点の種類（Auto・Bezier・Corner）は、下の中央のバーにいつも出し、対象の Keyframe が無いときは無効にする。
- Simplify のボタンは、タイムラインのバーにいつも出す。
- 今ある画面で、この決まりに合わない所が見つかったら、UI の作業で直す候補にする。
