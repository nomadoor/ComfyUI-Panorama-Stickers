# ADR 0042: Camera のレンズの曲線 κ

## Status

Accepted（2026-10-11）

## Date

2026-10-10

---

## 背景

ADR 0038 は、レンズ（歪み・魚眼・被写界深度）を機能の段で、UI の段より前に入れると決めた。描き方は ADR 0037 の「カメラの型」による：一つの光線の作り方をすべての層が使う。エディタは、余白付きの描画に後処理で像を曲げ、一致の許容差を別に置く。

オーナーの目的（2026-10-10）：

- レンズは主に絵作りのため。実機のカメラに合わせることは二の次。
- プリセットは作らない。直感で分かるカメラの値にする。
- 使い方の例：3D の Scene を魚眼で撮って下流で仕上げる。ドリーズーム（Camera の位置と画角を一緒に時間で変える）。
- 魚眼と歪みは切れ目なくつなぐ。
- 被写界深度は今は作らない（下の「次の候補」）。

## 決定

レンズの機能は、Camera の Lane `curve`（レンズの曲線 κ）一つだけにする。値は `camera` に直に Lane として置く（オーナーが承認）。ドリーズームは、今ある `position` と `fov` の Lane（と κ）に Keyframe を打って作る。

| 値 | 置き場 | 既定値 | 描き方への写し方 |
|---|---|---|---|
| 画角（今の `fov`、`hFOV_deg`） | 今の Lane | 90 | 画像の横の端の光線が光軸となす角の 2 倍（今と同じ意味）。上限は κ で決まる `min(360, 179 ÷ κ)` |
| レンズの曲線 κ | Lane `curve`（0〜1.5） | 1 | 光軸から θ の光線が像の中心から `r = f·tan(κθ) ÷ κ` に写る（κ = 0 は `r = f·θ`）。1 が今の直線の像、1 より大は糸巻き型、0.5 が立体射影、0 が等距離射影の魚眼。`f` は画角と今の κ から求める |

- κ を一つの連続した Lane にすることで、直線の像から魚眼までを Keyframe で切れ目なく動かせる（線形に補間する）。画素から光線への逆は `θ = atan(κr ÷ f) ÷ κ` で閉じているので、反復が要らない。θ が 180° を超える画素は `bg_color`。
- κ を変えても保つのは画角（端から端の角度。オーナーの決定）。κ を 0 に近づけると像の中心が大きくなるのは、魚眼の見た目として意図したもの。
- 輪を閉じる（オーナーの決定）：Pose handoff の配置の規則は κ によらず今のまま（動かない Camera は `sky`、動く Camera は `world`。条件で黙って振る舞いを変えない）。撮った `curve` を渡す。`sky` の Sticker は `curve` の Lane（既定 1）を持ち、Camera と同じ写し方の関数（`lens_radius`・`lens_angle`。Python と JS で一組、fixture で縛る）で標本化する。`world` の Sticker は `lens` の Lane（`curve` と `hFOV_deg`）を持てる。持たない Sticker は今の平らな板、持つ Sticker は κ = 1 も含めていつもレンズの中心のまわりの球面の一部（Pose handoff では Camera の位置を中心とする半径 2）に素材を同じ写し方で貼る（κ が 1 をまたいでも形が跳ばない）。Pose handoff は κ ≠ 1 のフレームがあるときだけ `lens` を足す。κ だけでは球面の一部の形が決まらない（半径か角度の広さがもう一つ要る）ので組にした。Pose handoff は Camera の値をフレームごとに焼く（ADR 0036）ので、どちらも値ではなく Lane にした。既定値は保存しない。Sticker の `curve`・`lens` にインスペクタの行は出さない（UI を最小にする。道具として使う行と、Pose handoff の `sky` と `world` の自動の切り替えが見えないことは UI の段の候補）。
- 焦点距離（mm）は状態に持たず、インスペクタで画角と並べて出す（36 mm 幅の仮定）。（2026-10-11 オーナーの決定で、この行は外した。H FOV と同じ値の二つ目の入口で紛らわしいため。`docs/editor-interaction.md`）
- エディタの κ ≠ 1：隅を覆うピンホールの画素の数が出力の 4 倍以下なら余白付きの描画と後処理、超えるなら立方体の 6 面と後処理。一つの規則で、κ と画角と比から決まる。
- 既定値（κ = 1）では今の出力が変わらず、保存するテキストに既定値を書かないので、今の状態のテキストもキャッシュも変わらない。主点のずらしは入れない。ERP には掛けない。

## 考えた別案

| 案 | 選ばなかった理由 |
|---|---|
| `projection` に Perspective / Fisheye の切り替えを足し、歪みは Brown–Conrady の k1 | 直線の像と魚眼の間に切れ目があり、時間で動かせない（オーナーは切れ目なくつなぐことを求めた）。Brown–Conrady の逆は反復が要る |
| Brown–Conrady のつまみ（k1・k2・p1・p2） | 実機のカメラに合わせる値で、絵作りには κ で足りる。次の候補とする |
| 焦点距離（mm）を状態に持つ | 今の `fov` の Lane と二重になり、ドリーズームの Keyframe が二つの値に分かれる |
| κ の範囲を 1.5 より広げる | 画角の上限が 120° を切り、隅の引き伸ばしが強すぎて絵作りの範囲を出る |
| プリセット | オーナーが作らないと決めた |

## 次の候補：被写界深度（今は作らない）

オーナーの決定（2026-10-10）：3DGS がもっときれいになるまで効かず、下流の AI が絵を描き直すので、今は作らない。状態にも値を足さない。作るときの覚え書き：

- 入射瞳（Camera の位置）に置いた薄いレンズ。開口の直径 = 焦点距離 ÷ F 値。焦点距離は 36 mm 幅のセンサーの仮定で画角と κ から求め、World の 1 単位を 1 m とする。ピントは光軸に垂直な平面。
- 開口の上の決まった N 点（乱数を使わない。Python と JS で同じ fixture）から 1 回ずつ描き、線形の光で平均する。画像の光線がすべて光軸から 90° 未満のときだけ定まる。
- 時間：ADR 0037 の計測から N = 16 で今の 16 倍の見込み（8K の光ありで約 9 秒）で、許容時間（8K 3 秒）を超える。

## Consequences

- 状態 v2 に Camera の `curve`、`sky` の Sticker の `curve`、`world` の Sticker の `lens` の Lane が加わり、`sticker_state` の `camera` に `curve` が加わる（parameter format の変更。オーナーが承認）。`fov`・`size`・`lens.hFOV_deg` の上限は κ に従う。
- 出力は κ ≠ 1 の `world` の Sticker を光線と球の交点で、エディタは球の帯の代わりの形と断片のシェーダで描く。
- 費用（RTX 4070 Ti、κ = 0.5、hFOV 140°、計測）：メッシュは 4K 0.43 秒・8K 1.54 秒で許容時間に収まる。スプラット（50 万）は 4K 1.25 秒・8K 5.58 秒で、κ = 1 でも 1.08 秒・4.23 秒と許容時間を超える。スプラットの速さは別の候補にする。
- スプラットの窓は光線の場から求める（ADR 0037）。κ ≠ 1 では slab を Camera からの距離で並べ、窓が画像の外に丸ごと出るガウシアンを先に除く。
- エディタに後処理のパスと立方体の 6 面の描画が加わる。余白付きの描画と立方体の面は線形の光で書くので、面の中の半透明の重なりは線形の光で混ざる。Frame 表示の重ね描きもレンズの写し方を通す。
- 行のポチはレンズの Lane（Camera の `curve` を含む）に Keyframe を入れない（Blender の LocRotScale と同じ）。レンズの値はその Lane の行で Keyframe にする。
- `sky` の Sticker の `size` の保存の範囲は 0.1〜360 になり、評価した値は `min(360, 179 ÷ κ)` に寄せる。
- エディタとの一致（llvmpipe）：メッシュの場面はすべての κ で合格した。スプラットの場面は κ = 1 でも合格しない（平均 1.99/255、8/255 超 14%）。レンズより前からあるエディタとノードのスプラットの描き方の差で、次の候補として残し、許容差は緩めない。
