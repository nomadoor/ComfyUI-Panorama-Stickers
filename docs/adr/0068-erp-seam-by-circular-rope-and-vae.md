# ADR 0068: ERP のつなぎ目は、横の RoPE の周期化と VAE の巻き付けで消す

## Status

Accepted（2026-11-26）

## Date

2026-11-26

---

## 背景

Qwen Image 2.1 で作った 360° ERP は、左右の端がつながらず、Preview で一周回すと縦の切れ目が見える。ERP outpaint LoRA
で切れ目はかなり軽くなったが、消えはしなかった。2026-09 には、VAE の decoder だけを横に circular にする試作を作ったが、
つなぎ目にファスナー状の乱れが出たので止めていた。

## 決定

ERP のつなぎ目を、decode の工夫ではなく、生成の段階で横の位置（RoPE）を周期的にすることと、VAE の encode と decode で
左右を巻き付けることの組み合わせで消す。2 つのノード Panorama Circular RoPE と Panorama Circular VAE にし、規則は
`docs/erp-circular.md` に書く。対象は Qwen Image 2.1 だけにする。

## 理由

- Qwen Image 2.1 の VAE の encoder は、zero padding のせいで、latent の左右の端から 10 列ほどに「ここが端」という印を
  書き込む。生成された latent も、この印を持つ。decoder だけを circular にすると、印どうしがぶつかってファスナー状の
  乱れになる。左右がもともとつながった実写の ERP でも、zero で encode して circular で decode すると同じ乱れが出て、
  circular で encode すると出ないことで確かめた。2026-09 の試作が失敗した理由は、内容のずれではなくこの印だった。
- decode の側でできることは、つなぎ目の近く数十 px を描き直すところまでで、latent の中身のずれ（岸の高さ、色味）は
  直せない。
- 横の RoPE を、画像の幅でちょうど整数回回る周波数にそろえると、モデルにとって左右の端が隣どうしになる。モデルは
  左右がつながった中身を描き、端の印も付けなくなる。そうした latent は、VAE を左右とも巻き付けて decode すれば、
  画素までつながる。学習は要らない。

## 確かめた範囲

2880×1440、RTX 4090。つなぎ目をはさむ 2 列の画素の差を「段差」、つなぎ目から離れた所の同じ値の中央値を「内側」とする。

| 条件 | 件数 | 普通の段差 | この方法の段差 | この方法の内側 |
|---|---|---|---|---|
| パノラマ用ワークフロー（参照画像あり） | 3 seed | 7.8〜10.2 | 4.9〜7.2 | 4.6〜5.8 |
| 人の多い text2image（夜市・カフェ・駅） | 6 | 11.5〜25.2 | 4.1〜9.6 | 4.3〜8.7 |
| ERP outpainting（緑の参照画像、LoRA なし／あり） | 4 | 8.7〜11.2 | 3.3〜6.4 | 3.7〜7.2 |
| ERP outpainting（参照画像を resolution 1024 に縮めた） | 1 | 10.7 | 3.4 | 4.2 |

どの条件でも、latent の左端と右端の差は、内側で隣り合う列どうしの差と同じになった（端の印が消えた）。

## 考えた別案

- decoder だけを circular にする（2026-09 の試作）。ファスナーが出る。
- decoder の前の段だけ zero のまま残す、端の印を見積もって引く、端の列を入れ替える、端の印を実写の ERP 70 枚から
  覚えさせて消す。どれもつなぎ目の近くを描き直すだけで、中身のずれは残る。
- 毎ステップ、latent の左右に反対側を足してからモデルに通す。つなぎ目はつながるが、絵が少し荒れ、端の印も半分残る。
- 横の全周波数をそろえる。ゆっくり回る帯まで変えると構図を変えてしまうおそれがあるので、0.5 回を超えて回る帯だけにした
  （どちらでもつなぎ目は消えた）。
- VAE の層を、巻き付ける module で包んで差し替える。ComfyUI がモデルを出し入れするときに使う層の名前が変わるので
  採らない。encoder と decoder の外側でまとめて広げて切り落とす案は、中段に画像全体を見る attention があり、厳密な
  circular にならないので採らない。

## 同じ考え方の先行研究

SHERPA（arXiv:2606.12213）は、FLUX の横の RoPE の高い周波数を整数周期にそろえている。SpheRoPE（arXiv:2606.32033）は、
学習なしで FLUX と LTX-Video の RoPE を周期化している。どちらも Qwen Image 2.1 は対象にしていない。360Anything
（arXiv:2601.16192）は、ERP のつなぎ目の原因を VAE の encoder の zero padding だとしている。

## 影響

- 2 つのノードは必ずセットで使う。片方だけだと端に乱れが出る。
- Circular VAE は tiled を断るので、VRAM の小さい環境では、今まで tiled で通っていた decode がエラーになる。
- Panorama Circular VAE は `VAE.clone()`（ComfyUI v0.44.0 から）を使う。CI の ComfyUI は v0.42.0 のままにし（v0.45 系に
  上げると、動画の container の規則と Spark の版で、この変更と関係ない test が落ちるため）、`VAE.clone()` の無い core では
  VAE の test を skip する。CI の固定を上げるのは、新しい core への追従と一緒に別の作業で行う。
- ほかのモデル（FLUX.2、MiniMax H3 Image など）は、位置の表し方と VAE の作りがそれぞれ違うので、1 つずつ確かめてから
  足す。
